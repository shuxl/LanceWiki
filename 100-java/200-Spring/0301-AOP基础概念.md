# 2 AOP概念或介绍

## 2.1 什么是AOP
AOP（Aspect-Oriented Programming，面向切面编程）是一种编程范式，它允许开发者将横切关注点（cross-cutting concerns）从主业务逻辑中分离出来。横切关注点是指那些在多个模块中重复出现的功能，如日志记录、事务管理、安全检查等。

## 2.2 AOP的核心思想
AOP的核心思想是"关注点分离"：
- **单一职责原则**：每个模块只负责自己的核心业务逻辑
- **横切关注点**：将公共功能（如日志、事务、安全）从业务代码中提取出来
- **模块化**：通过切面（Aspect）来组织和管理横切关注点

## 2.3 AOP与OOP的关系
- **OOP（面向对象编程）**：关注对象和类的设计，强调封装、继承、多态
- **AOP（面向切面编程）**：关注横切关注点的处理，强调关注点分离
- **互补关系**：AOP是对OOP的补充，两者结合使用能更好地实现软件设计目标

# 3 AOP核心术语

## 3.1 切面（Aspect）
切面是横切关注点的模块化，它包含了通知和切点的组合。

```java
@Aspect
@Component
public class LoggingAspect {
    // 切面类，包含通知和切点
}
```

## 3.2 连接点（Join Point）
程序执行过程中能够插入切面的点，如方法调用、方法执行、异常处理等。

```java
// 方法调用是一个连接点
public void businessMethod() {
    // 业务逻辑
}
```

## 3.3 切点（Pointcut）
匹配连接点的表达式，用于确定在哪些连接点应用通知。

```java
@Pointcut("execution(* com.example.service.*.*(..))")
public void serviceLayer() {
    // 切点表达式，匹配service包下所有类的所有方法
}
```

## 3.4 通知（Advice）
在切点处要执行的代码，定义了"何时"执行。

### 3.4.1 通知类型：
- **前置通知（@Before）**：在目标方法执行前执行
- **后置通知（@AfterReturning）**：在目标方法成功执行后执行
- **异常通知（@AfterThrowing）**：在目标方法抛出异常时执行
- **最终通知（@After）**：无论目标方法是否成功执行都会执行
- **环绕通知（@Around）**：包围目标方法的执行，可以控制是否执行目标方法

```java
@Before("serviceLayer()")
public void beforeAdvice(JoinPoint joinPoint) {
    System.out.println("方法执行前：" + joinPoint.getSignature().getName());
}

@Around("serviceLayer()")
public Object aroundAdvice(ProceedingJoinPoint joinPoint) throws Throwable {
    System.out.println("方法执行前");
    Object result = joinPoint.proceed(); // 执行目标方法
    System.out.println("方法执行后");
    return result;
}
```

## 3.5 目标对象（Target Object）
被代理的对象，包含核心业务逻辑。

```java
@Service
public class UserService {
    public void createUser() {
        // 核心业务逻辑
    }
}
```

## 3.6 代理（Proxy）
AOP框架创建的对象，用于实现切面契约。代理对象包含目标对象和通知。

# 4 Spring AOP的实现原理

## 4.1 代理模式
Spring AOP基于代理模式实现，主要有两种代理方式：

### 4.1.1 JDK动态代理
- **适用场景**：目标类实现了接口
- **原理**：基于接口创建代理对象
- **优势**：性能较好，无需额外依赖

```java
// 目标接口
public interface UserService {
    void createUser();
}

// 目标类
public class UserServiceImpl implements UserService {
    public void createUser() {
        // 业务逻辑
    }
}

// JDK动态代理会创建实现UserService接口的代理类
```

### 4.1.2 CGLIB代理
- **适用场景**：目标类没有实现接口
- **原理**：通过继承目标类创建子类代理
- **优势**：可以代理没有接口的类

```java
// 目标类（没有接口）
public class UserService {
    public void createUser() {
        // 业务逻辑
    }
}

// CGLIB会创建UserService的子类作为代理
```

## 4.2 代理创建过程
1. **解析切点表达式**：确定哪些方法需要被代理
2. **创建代理对象**：根据目标类是否有接口选择代理方式
3. **织入通知**：将通知代码织入到代理对象中
4. **返回代理对象**：用代理对象替换原始对象

# 5 Spring AOP的优势

## 5.1 关注点分离
- 业务逻辑与横切关注点分离
- 提高代码的可维护性和可读性

## 5.2 代码复用
- 横切关注点可以在多个模块中复用
- 减少重复代码

## 5.3 易于维护
- 修改横切关注点时，只需要修改切面代码
- 不影响业务逻辑代码

## 5.4 动态性
- 可以在运行时动态地添加或移除切面
- 支持条件化的切面应用

# 6 AOP使用场景

## 6.1 日志记录
```java
@Aspect
@Component
public class LoggingAspect {
    @Before("execution(* com.example.service.*.*(..))")
    public void logBefore(JoinPoint joinPoint) {
        System.out.println("执行方法：" + joinPoint.getSignature().getName());
    }
}
```

## 6.2 事务管理
```java
@Transactional
public void createUser() {
    // 业务逻辑
}
```

## 6.3 性能监控
```java
@Aspect
@Component
public class PerformanceAspect {
    @Around("execution(* com.example.service.*.*(..))")
    public Object measureTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long end = System.currentTimeMillis();
        System.out.println("方法执行时间：" + (end - start) + "ms");
        return result;
    }
}
```

## 6.4 安全检查
```java
@Aspect
@Component
public class SecurityAspect {
    @Before("@annotation(secured)")
    public void checkSecurity(JoinPoint joinPoint, Secured secured) {
        // 安全检查逻辑
    }
}
```
