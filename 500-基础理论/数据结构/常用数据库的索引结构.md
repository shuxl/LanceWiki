# 1 **数据库索引类型总览**

|**索引类型**|**底层数据结构**|**主要特点**|**适用场景**|**优点**|**缺点**|**对比**|
|---|---|---|---|---|---|---|
|**B-Tree**|多路平衡搜索树|数据可存储在所有节点|单值查询、范围查询|查找效率 O(log n)，支持范围查询|范围扫描比 B+ Tree 稍慢，节点大小不均|与 B+ Tree 比：范围扫描弱，但单值命中可提前结束|
|**B+ Tree**|多路平衡搜索树 + 叶子链表|数据只存储在叶子节点，非叶节点存索引|数据库主键/二级索引|范围查询效率高，节点扇出大，磁盘 IO 少|单值查询必须到叶子节点|MySQL InnoDB 默认索引结构|
|**R-Tree**|多维空间索引树|每个节点存储空间矩形（MBR）|GIS、地图、几何数据|支持二维/多维范围查询|插入删除复杂，更新代价大|对比 B+ Tree：多维数据场景优势明显|
|**Hash 索引**|哈希表|key 经过哈希函数直接定位数据|等值查询（=、IN）|查询复杂度 O(1)，超快等值查找|不支持范围查询，哈希冲突需处理|对比 B+ Tree：等值快，范围差|
|**位图索引**|位图（Bit Array）|用位表示某列值的存在情况|低基数字段（性别、状态码）|空间占用小，布尔计算快|高基数字段占用大，更新代价高|对比 B+ Tree：低基数快得多|
|**倒排索引**|哈希表 / B+ Tree + Posting List|词 → 文档列表映射|全文搜索、日志检索|模糊/关键词搜索快，支持排名|维护成本高，占用较大空间|Elasticsearch、Lucene核心结构|
|**全文索引**|倒排索引|文本字段关键词索引|模糊搜索、搜索引擎|搜索速度快，支持分词|插入/更新慢|MySQL MyISAM/ InnoDB（FULLTEXT）|
|**LSM-Tree**|有序 SSTable + MemTable|写优先，批量刷盘合并|高写入量场景|写入快，顺序读快|随机读性能较差，需要合并|RocksDB、HBase、Cassandra 核心|
|**跳表（Skip List）**|多层链表 + 随机索引|平均 O(log n) 查询|有序数据、范围查询|实现简单，范围扫描快|占用空间较多|Redis ZSet、LevelDB 用|
|**聚簇索引（Clustered Index）**|B+ Tree|数据与索引存储在一起|主键索引|主键范围查询快|更新代价大（移动行）|MySQL InnoDB 主键索引|
|**非聚簇索引（Non-clustered Index）**|B+ Tree|索引和数据分离|二级索引|适合多列组合查询|需要回表查询|SQL Server/ MySQL 二级索引|

# 2 **强对比索引**

## 2.1 **B-Tree vs B+ Tree**

|**特性**|**B-Tree**|**B+ Tree**|
|---|---|---|
|数据存储位置|内部节点 + 叶子|仅叶子|
|范围查询|中序遍历全树|顺序扫描叶子链表|
|磁盘 I/O|节点数据多，扇出小|节点小，扇出大，I/O 少|
|场景|单值查找、文件系统|数据库主键/二级索引|

---

## 2.2 **Hash 索引 vs B+ Tree 索引**

|**特性**|**Hash 索引**|**B+ Tree 索引**|
|---|---|---|
|等值查询|O(1)，最快|O(log n)|
|范围查询|不支持|支持|
|顺序访问|不支持|支持|
|碰撞处理|需要额外机制|不存在冲突问题|
|场景|高速等值查找|范围+等值综合查询|

---

## 2.3 **位图索引 vs B+ Tree 索引**

|**特性**|**位图索引**|**B+ Tree 索引**|
|---|---|---|
|适用列|低基数|任意基数|
|查询速度|低基数超快|综合表现好|
|空间占用|高基数占用大|稳定|
|更新代价|高|中|
|场景|OLAP 数据仓库|OLTP 系统主流|

---

# 3 **总结**
- **通用型**：B+ Tree（MySQL、PostgreSQL 默认）
- **等值查询极快**：Hash 索引
- **低基数分析**：位图索引
- **全文检索**：倒排索引
- **高写入量**：LSM-Tree
- **多维空间**：R-Tree
- **内存有序集合**：跳表
