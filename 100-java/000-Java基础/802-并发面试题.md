# 2 线程基础概念

## 2.1 什么是线程？线程与进程的区别？

**线程**是程序执行的最小单位，是CPU调度的基本单位。一个进程可以包含多个线程，线程共享进程的资源。

**区别：**
- **资源分配**：进程是资源分配的基本单位，线程是CPU调度的基本单位
- **内存空间**：进程有独立的内存空间，线程共享所属进程的内存空间
- **创建开销**：创建进程开销大，创建线程开销小
- **通信方式**：进程间通信需要特殊机制，线程间可以直接通信

## 2.2 线程的生命周期有哪些状态？

```java
// 线程状态枚举
public enum State {
    NEW,           // 新建状态
    RUNNABLE,      // 可运行状态
    BLOCKED,       // 阻塞状态
    WAITING,       // 等待状态
    TIMED_WAITING, // 限时等待状态
    TERMINATED     // 终止状态
}
```

**状态转换：**
- NEW → RUNNABLE：调用start()方法
- RUNNABLE → BLOCKED：等待获取锁
- RUNNABLE → WAITING：调用wait()、join()、park()
- RUNNABLE → TIMED_WAITING：调用sleep()、wait(timeout)、parkNanos()
- BLOCKED/WAITING/TIMED_WAITING → RUNNABLE：被唤醒或获得锁

## 2.3 如何创建线程？推荐哪种方式？

**创建方式：**
1. 继承Thread类
2. 实现Runnable接口
3. 实现Callable接口（有返回值）
4. 使用线程池

**推荐使用Runnable接口：**
- 避免单继承限制
- 更好的代码复用性
- 符合面向接口编程原则

```java
// 推荐方式
public class MyRunnable implements Runnable {
    @Override
    public void run() {
        // 线程执行逻辑
    }
}

// 使用
Thread thread = new Thread(new MyRunnable());
thread.start();
```

# 3 线程安全与同步机制

## 3.1 什么是线程安全？如何保证线程安全？

**线程安全**：多线程环境下，程序能够正确执行，不会出现数据不一致或异常。

**保证方式：**
1. **无状态设计**：不共享状态
2. **不可变对象**：使用final关键字
3. **同步机制**：synchronized、volatile、锁
4. **线程安全容器**：ConcurrentHashMap、CopyOnWriteArrayList等

## 3.2 synchronized关键字的作用和原理？

**作用：**
- 保证方法或代码块的原子性
- 保证可见性
- 保证有序性

**原理：**
- 基于对象头中的Mark Word
- 通过monitor锁机制实现
- 偏向锁 → 轻量级锁 → 重量级锁的升级过程

```java
// 对象锁
public synchronized void method() {
    // 临界区代码
}

// 类锁
public static synchronized void staticMethod() {
    // 临界区代码
}

// 代码块锁
public void blockMethod() {
    synchronized(this) {
        // 临界区代码
    }
}
```

## 3.3 volatile关键字的作用和原理？

**作用：**
- 保证可见性
- 禁止指令重排序
- 不保证原子性

**原理：**
- 通过内存屏障实现
- 写操作时刷新到主内存
- 读操作时从主内存读取最新值

```java
public class VolatileExample {
    private volatile boolean flag = false;
    
    public void write() {
        flag = true; // 写操作，立即刷新到主内存
    }
    
    public void read() {
        while (!flag) {
            // 读操作，从主内存读取最新值
        }
    }
}
```

## 3.4 synchronized和volatile的区别？

| 特性 | synchronized | volatile |
|------|-------------|----------|
| 原子性 | 保证 | 不保证 |
| 可见性 | 保证 | 保证 |
| 有序性 | 保证 | 保证 |
| 性能 | 较重 | 较轻 |
| 使用场景 | 复杂同步 | 简单可见性 |

# 4 锁机制和并发工具类

## 4.1 ReentrantLock和synchronized的区别？

**ReentrantLock优势：**
- 可中断锁
- 公平锁选择
- 多个条件变量
- 可限时获取锁

```java
public class LockExample {
    private ReentrantLock lock = new ReentrantLock();
    
    public void method() {
        lock.lock();
        try {
            // 临界区代码
        } finally {
            lock.unlock();
        }
    }
}
```

## 4.2 什么是死锁？如何避免死锁？

**死锁条件：**
1. 互斥条件
2. 请求与保持条件
3. 不剥夺条件
4. 循环等待条件

**避免策略：**
- 一次性申请所有资源
- 按顺序申请资源
- 使用超时机制
- 银行家算法

## 4.3 什么是线程池？为什么使用线程池？

**线程池优势：**
- 降低资源消耗
- 提高响应速度
- 提高线程可管理性
- 提供更多功能

**核心参数：**
- corePoolSize：核心线程数
- maximumPoolSize：最大线程数
- keepAliveTime：线程空闲时间
- workQueue：工作队列
- threadFactory：线程工厂
- handler：拒绝策略

```java
// 创建线程池
ExecutorService executor = Executors.newFixedThreadPool(10);

// 提交任务
executor.submit(() -> {
    // 任务逻辑
});

// 关闭线程池
executor.shutdown();
```

# 5 内存模型和可见性问题

## 5.1 什么是Java内存模型（JMM）？

**JMM定义：**
- 定义了Java虚拟机在计算机内存中的工作方式
- 屏蔽了各种硬件和操作系统的内存访问差异
- 保证Java程序在各种平台上都能达到一致的内存访问效果

**三大特性：**
- **原子性**：操作不可中断
- **可见性**：一个线程的修改对其他线程可见
- **有序性**：程序执行顺序符合预期

## 5.2 什么是happens-before原则？

**happens-before关系：**
- 程序顺序规则
- 监视器锁规则
- volatile变量规则
- 线程启动规则
- 线程终止规则
- 中断规则
- 终结器规则
- 传递性规则

## 5.3 什么是CAS？CAS的ABA问题如何解决？

**CAS（Compare And Swap）：**
- 比较并交换的原子操作
- 乐观锁的实现方式
- 无锁编程的基础

**ABA问题：**
- 值从A变为B，再变回A
- 使用版本号或时间戳解决

```java
// 使用AtomicStampedReference解决ABA问题
AtomicStampedReference<String> atomicRef = 
    new AtomicStampedReference<>("A", 1);

// 更新时同时更新版本号
atomicRef.compareAndSet("A", "B", 1, 2);
```

# 6 高级并发工具

## 6.1 CountDownLatch、CyclicBarrier、Semaphore的区别？

**CountDownLatch：**
- 一次性使用
- 等待多个线程完成

**CyclicBarrier：**
- 可重复使用
- 等待多个线程到达同步点

**Semaphore：**
- 控制并发访问数量
- 信号量机制

## 6.2 什么是ThreadLocal？使用场景和注意事项？

**ThreadLocal：**
- 线程本地变量
- 每个线程独立的变量副本

**使用场景：**
- 数据库连接
- Session管理
- 用户身份信息

**注意事项：**
- 内存泄漏风险
- 及时清理
- 使用try-finally确保清理

```java
public class ThreadLocalExample {
    private static ThreadLocal<String> threadLocal = new ThreadLocal<>();
    
    public void setValue(String value) {
        threadLocal.set(value);
    }
    
    public String getValue() {
        return threadLocal.get();
    }
    
    public void remove() {
        threadLocal.remove(); // 防止内存泄漏
    }
}
```
