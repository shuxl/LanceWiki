# 2 JVM垃圾回收机制概念或介绍

JVM垃圾回收机制是Java虚拟机自动管理内存的核心机制，负责识别和回收不再使用的对象，释放内存空间。垃圾回收是Java语言的重要特性，使开发者无需手动管理内存。

## 2.1 垃圾回收概述
垃圾回收机制的主要功能：
- **自动内存管理**：无需手动释放内存
- **内存碎片整理**：减少内存碎片
- **性能优化**：通过不同的回收策略优化性能
- **内存安全**：防止内存泄漏和溢出

# 3 垃圾回收基本原理

## 3.1 什么是垃圾
垃圾是指程序中不再被引用的对象：
- **无引用对象**：没有任何引用指向的对象
- **循环引用对象**：相互引用但无外部引用的对象
- **临时对象**：生命周期已结束的对象

## 3.2 垃圾回收算法

### 3.2.1 标记-清除算法（Mark-Sweep）
标记-清除算法分为两个阶段：

**标记阶段**：
- 从根对象开始遍历
- 标记所有可达的对象
- 未被标记的对象即为垃圾

**清除阶段**：
- 清除所有未被标记的对象
- 释放内存空间

**优缺点**：
- **优点**：实现简单，效率较高
- **缺点**：会产生内存碎片

### 3.2.2 复制算法（Copying）
复制算法将内存分为两个相等的区域：

**工作原理**：
- 将存活对象复制到另一个区域
- 清空当前区域
- 交换两个区域的角色

**优缺点**：
- **优点**：无内存碎片，效率高
- **缺点**：内存利用率低，只能使用一半内存

### 3.2.3 标记-整理算法（Mark-Compact）
标记-整理算法结合了标记-清除和复制算法的优点：

**工作过程**：
1. **标记阶段**：标记所有可达对象
2. **整理阶段**：将存活对象向一端移动
3. **清除阶段**：清除边界外的内存

**优缺点**：
- **优点**：无内存碎片，内存利用率高
- **缺点**：整理过程耗时较长

### 3.2.4 分代收集算法（Generational Collection）
分代收集算法根据对象生命周期特点采用不同策略：

**分代策略**：
- **新生代**：使用复制算法
- **老年代**：使用标记-整理或标记-清除算法

# 4 分代垃圾回收

## 4.1 分代回收原理
根据对象存活时间将内存分为不同代：

```
堆内存
├── 新生代（Young Generation）
│   ├── Eden区（80%）
│   └── Survivor区（20%）
│       ├── From区（10%）
│       └── To区（10%）
└── 老年代（Old Generation）
```

## 4.2 新生代垃圾回收

### 4.2.1 Minor GC过程
1. **Eden区分配**：新对象分配在Eden区
2. **Eden区满时触发Minor GC**：当Eden区空间不足时
3. **标记存活对象**：标记Eden区和From区的存活对象
4. **复制到To区**：将存活对象复制到To区
5. **交换From和To**：交换From区和To区的角色
6. **晋升到老年代**：存活次数达到阈值的对象晋升到老年代

### 4.2.2 对象晋升条件
- **年龄阈值**：对象在Survivor区存活次数达到阈值（默认15次）
- **空间不足**：Survivor区空间不足时，部分对象直接晋升
- **大对象**：大对象直接进入老年代

## 4.3 老年代垃圾回收

### 4.3.1 Major GC过程
1. **触发条件**：老年代空间不足时触发
2. **标记阶段**：标记所有可达对象
3. **整理阶段**：将存活对象向一端移动
4. **清除阶段**：清除边界外的内存

### 4.3.2 Full GC
Full GC是对整个堆进行垃圾回收，包括：
- **新生代**：Minor GC
- **老年代**：Major GC
- **方法区**：回收无用的类信息

# 5 垃圾回收器

## 5.1 垃圾回收器分类

### 5.1.1 按线程数分类
- **串行回收器**：单线程执行垃圾回收
- **并行回收器**：多线程并行执行垃圾回收
- **并发回收器**：垃圾回收线程与用户线程并发执行

### 5.1.2 按工作模式分类
- **独占式回收器**：垃圾回收时暂停所有用户线程
- **并发式回收器**：垃圾回收时用户线程可以继续执行

## 5.2 常用垃圾回收器

### 5.2.1 Serial收集器
- **特点**：单线程串行收集器
- **适用场景**：客户端应用，内存较小
- **参数**：`-XX:+UseSerialGC`

### 5.2.2 ParNew收集器
- **特点**：Serial的多线程版本
- **适用场景**：多核CPU环境
- **参数**：`-XX:+UseParNewGC`

### 5.2.3 Parallel Scavenge收集器
- **特点**：关注吞吐量的并行收集器
- **适用场景**：后台计算任务
- **参数**：`-XX:+UseParallelGC`

### 5.2.4 CMS收集器
- **特点**：低延迟的并发收集器
- **适用场景**：对响应时间要求高的应用
- **参数**：`-XX:+UseConcMarkSweepGC`

### 5.2.5 G1收集器
- **特点**：可预测停顿时间的收集器
- **适用场景**：大内存应用
- **参数**：`-XX:+UseG1GC`

### 5.2.6 ZGC收集器
- **特点**：低延迟的并发收集器
- **适用场景**：对延迟要求极高的应用
- **参数**：`-XX:+UseZGC`

# 6 垃圾回收性能调优

## 6.1 调优目标
- **吞吐量**：应用程序运行时间占总时间的比例
- **延迟**：垃圾回收的停顿时间
- **内存使用**：堆内存的使用效率

## 6.2 调优参数

### 6.2.1 堆内存参数
- `-Xms`：初始堆大小
- `-Xmx`：最大堆大小
- `-Xmn`：新生代大小
- `-XX:NewRatio`：新生代与老年代的比例
- `-XX:SurvivorRatio`：Eden区与Survivor区的比例

### 6.2.2 垃圾回收器参数
- `-XX:+UseSerialGC`：使用Serial收集器
- `-XX:+UseParallelGC`：使用Parallel Scavenge收集器
- `-XX:+UseConcMarkSweepGC`：使用CMS收集器
- `-XX:+UseG1GC`：使用G1收集器

### 6.2.3 性能监控参数
- `-XX:+PrintGC`：打印GC日志
- `-XX:+PrintGCDetails`：打印详细GC日志
- `-XX:+PrintGCTimeStamps`：打印GC时间戳
- `-XX:+PrintGCApplicationStoppedTime`：打印应用停顿时间

## 6.3 调优策略

### 6.3.1 吞吐量优先
- **目标**：最大化应用程序运行时间
- **策略**：使用Parallel Scavenge收集器
- **参数**：`-XX:+UseParallelGC -XX:MaxGCPauseMillis=200`

### 6.3.2 延迟优先
- **目标**：最小化垃圾回收停顿时间
- **策略**：使用G1或ZGC收集器
- **参数**：`-XX:+UseG1GC -XX:MaxGCPauseMillis=10`

### 6.3.3 内存使用优先
- **目标**：最小化内存使用
- **策略**：合理设置堆大小，避免频繁GC
- **参数**：根据应用特点调整堆大小

# 7 内存泄漏问题

## 7.1 内存泄漏原因
1. **静态集合**：静态集合持有对象引用
2. **监听器未移除**：事件监听器未正确移除
3. **内部类持有外部类引用**：内部类持有外部类引用导致无法回收
4. **数据库连接未关闭**：数据库连接未正确关闭
5. **线程池未关闭**：线程池未正确关闭

## 7.2 内存泄漏检测
1. **使用工具**：MAT、JProfiler等工具分析堆转储文件
2. **监控指标**：监控堆内存使用情况和GC频率
3. **代码审查**：检查代码中的资源管理

## 7.3 内存泄漏解决
1. **及时释放资源**：确保资源在不再使用时被释放
2. **使用弱引用**：对于缓存等场景使用弱引用
3. **避免循环引用**：避免对象之间的循环引用
4. **使用工具类**：使用try-with-resources等工具类
