# 2 事务回滚机制概念或介绍

## 2.1 什么是事务回滚
事务回滚（Transaction Rollback）是指当事务执行过程中发生异常或错误时，将事务中的所有修改撤销，使数据库恢复到事务开始前的状态。回滚是保证事务原子性的重要机制。

## 2.2 回滚机制的作用
- **数据一致性保证**：确保事务的原子性
- **错误恢复**：从异常状态恢复到正常状态
- **并发控制**：处理并发冲突和死锁
- **业务逻辑保护**：防止部分操作成功导致的数据不一致

# 3 回滚触发条件

## 3.1 自动回滚条件
Spring事务在以下情况下会自动回滚：

### 3.1.1 运行时异常
```java
@Service
public class UserService {
    
    @Transactional
    public void createUser(User user) {
        userRepository.save(user);
        
        // 运行时异常，事务自动回滚
        if (user.getAge() < 0) {
            throw new IllegalArgumentException("Age cannot be negative");
        }
        
        profileService.createProfile(user.getId());
    }
}
```

### 3.1.2 错误异常
```java
@Service
public class PaymentService {
    
    @Transactional
    public void processPayment(Payment payment) {
        // 业务逻辑
        paymentRepository.save(payment);
        
        // Error异常，事务自动回滚
        if (payment.getAmount().compareTo(BigDecimal.ZERO) <= 0) {
            throw new Error("Invalid payment amount");
        }
        
        accountService.updateBalance(payment.getAccountId(), payment.getAmount());
    }
}
```

### 3.1.3 手动设置回滚标记
```java
@Service
public class OrderService {
    
    @Transactional
    public void createOrder(Order order) {
        orderRepository.save(order);
        
        // 手动设置回滚标记
        TransactionAspectSupport.currentTransactionStatus().setRollbackOnly();
        
        // 后续操作不会执行，事务会回滚
        inventoryService.updateStock(order.getItems());
    }
}
```

## 3.2 不回滚条件
以下情况下事务不会自动回滚：

### 3.2.1 受检异常
```java
@Service
public class FileService {
    
    @Transactional
    public void processFile(String filePath) throws IOException {
        // 受检异常，默认不回滚
        if (!Files.exists(Paths.get(filePath))) {
            throw new IOException("File not found");
        }
        
        // 处理文件
        processFileContent(filePath);
    }
}
```

### 3.2.2 自定义异常
```java
@Service
public class NotificationService {
    
    @Transactional
    public void sendNotification(Notification notification) {
        // 自定义异常，默认不回滚
        if (notification.getPriority() == Priority.LOW) {
            throw new LowPriorityException("Low priority notification");
        }
        
        // 发送通知
        notificationRepository.save(notification);
    }
}
```

# 4 回滚策略配置

## 4.1 默认回滚策略
Spring事务默认只对运行时异常和错误进行回滚：

```java
@Transactional
public void businessMethod() {
    // 运行时异常 - 回滚
    throw new RuntimeException("Runtime exception");
    
    // 受检异常 - 不回滚
    throw new IOException("Checked exception");
}
```

## 4.2 自定义回滚策略

### 4.2.1 指定回滚异常
```java
@Transactional(rollbackFor = {IOException.class, SQLException.class})
public void processData() throws IOException {
    // 处理数据
    dataRepository.save(data);
    
    // 指定异常会触发回滚
    if (data.isInvalid()) {
        throw new IOException("Invalid data");
    }
}
```

### 4.2.2 指定不回滚异常
```java
@Transactional(noRollbackFor = {BusinessException.class})
public void processOrder(Order order) {
    // 处理订单
    orderRepository.save(order);
    
    // 指定异常不会触发回滚
    if (order.getAmount() > 10000) {
        throw new BusinessException("Order amount too high");
    }
}
```

### 4.2.3 混合配置
```java
@Transactional(
    rollbackFor = {IOException.class, SQLException.class},
    noRollbackFor = {BusinessException.class}
)
public void complexBusinessMethod() throws IOException {
    // 复杂的业务逻辑
    // 只有指定的异常会触发回滚
}
```

# 5 回滚实现原理

## 5.1 数据库层面的回滚

### 5.1.1 日志回滚
```java
public class DatabaseRollbackManager {
    
    private List<LogEntry> transactionLog = new ArrayList<>();
    
    public void logOperation(String operation, Object data) {
        LogEntry entry = new LogEntry(operation, data, System.currentTimeMillis());
        transactionLog.add(entry);
    }
    
    public void rollback() {
        // 按相反顺序执行回滚操作
        for (int i = transactionLog.size() - 1; i >= 0; i--) {
            LogEntry entry = transactionLog.get(i);
            executeRollbackOperation(entry);
        }
        
        // 清空日志
        transactionLog.clear();
    }
    
    private void executeRollbackOperation(LogEntry entry) {
        switch (entry.getOperation()) {
            case "INSERT":
                // 删除插入的数据
                deleteRecord(entry.getData());
                break;
            case "UPDATE":
                // 恢复更新前的数据
                restoreRecord(entry.getData());
                break;
            case "DELETE":
                // 恢复删除的数据
                insertRecord(entry.getData());
                break;
        }
    }
}
```

### 5.1.2 保存点回滚
```java
public class SavepointRollbackManager {
    
    private Map<String, Savepoint> savepoints = new HashMap<>();
    
    public Savepoint createSavepoint(String name) {
        try {
            Connection con = getCurrentConnection();
            Savepoint savepoint = con.setSavepoint(name);
            savepoints.put(name, savepoint);
            return savepoint;
        } catch (SQLException e) {
            throw new TransactionSystemException("Could not create savepoint", e);
        }
    }
    
    public void rollbackToSavepoint(String name) {
        Savepoint savepoint = savepoints.get(name);
        if (savepoint != null) {
            try {
                Connection con = getCurrentConnection();
                con.rollback(savepoint);
            } catch (SQLException e) {
                throw new TransactionSystemException("Could not rollback to savepoint", e);
            }
        }
    }
}
```

## 5.2 Spring层面的回滚

### 5.2.1 回滚处理流程
```java
public class TransactionAspectSupport {
    
    protected void completeTransactionAfterThrowing(TransactionAttribute txAttr, 
                                                  TransactionStatus status, 
                                                  Throwable ex) {
        // 1. 判断是否需要回滚
        if (txAttr.rollbackOn(ex)) {
            try {
                // 2. 执行回滚
                txAttr.getTransactionManager().rollback(status);
            } catch (TransactionSystemException ex2) {
                // 3. 记录回滚异常
                logger.error("Application exception overridden by rollback exception", ex);
                throw ex2;
            } catch (RuntimeException ex2) {
                // 4. 记录回滚异常
                logger.error("Application exception overridden by rollback exception", ex);
                throw ex2;
            } catch (Error err) {
                // 5. 记录回滚异常
                logger.error("Application exception overridden by rollback exception", ex);
                throw err;
            }
        } else {
            // 6. 提交事务
            txAttr.getTransactionManager().commit(status);
        }
    }
}
```

### 5.2.2 回滚判断逻辑
```java
public class RuleBasedTransactionAttribute extends DefaultTransactionAttribute {
    
    private List<RollbackRuleAttribute> rollbackRules = new ArrayList<>();
    private List<NoRollbackRuleAttribute> noRollbackRules = new ArrayList<>();
    
    @Override
    public boolean rollbackOn(Throwable ex) {
        // 1. 检查不回滚规则
        for (NoRollbackRuleAttribute rule : noRollbackRules) {
            if (rule.getDepth(ex) >= 0) {
                return false;
            }
        }
        
        // 2. 检查回滚规则
        for (RollbackRuleAttribute rule : rollbackRules) {
            if (rule.getDepth(ex) >= 0) {
                return true;
            }
        }
        
        // 3. 默认规则：运行时异常和错误回滚
        return (ex instanceof RuntimeException || ex instanceof Error);
    }
}
```

### 5.2.3 异常深度匹配
```java
public class RollbackRuleAttribute {
    
    private Class<?> exceptionClass;
    
    public int getDepth(Throwable ex) {
        return getDepth(ex.getClass(), 0);
    }
    
    private int getDepth(Class<?> exceptionClass, int depth) {
        if (exceptionClass == null) {
            return -1;
        }
        
        // 检查当前异常类是否匹配
        if (this.exceptionClass.equals(exceptionClass)) {
            return depth;
        }
        
        // 递归检查父类
        return getDepth(exceptionClass.getSuperclass(), depth + 1);
    }
}
```

# 6 回滚机制的最佳实践

## 6.1 异常处理策略

### 6.1.1 分层异常处理
```java
@Service
public class LayeredExceptionService {
    
    @Transactional(rollbackFor = {DataAccessException.class})
    public void processData() {
        try {
            // 数据访问层异常
            dataRepository.save(data);
        } catch (DataAccessException e) {
            // 数据访问异常，回滚事务
            throw e;
        } catch (BusinessException e) {
            // 业务异常，不回滚事务
            log.error("Business exception occurred", e);
        } catch (Exception e) {
            // 其他异常，回滚事务
            throw new RuntimeException("Unexpected error", e);
        }
    }
}
```

### 6.1.2 异常转换
```java
@Service
public class ExceptionConversionService {
    
    @Transactional
    public void processOrder(Order order) {
        try {
            // 业务逻辑
            orderRepository.save(order);
            paymentService.processPayment(order.getPayment());
        } catch (PaymentException e) {
            // 将支付异常转换为运行时异常，触发回滚
            throw new RuntimeException("Payment processing failed", e);
        } catch (ValidationException e) {
            // 验证异常，不回滚
            log.warn("Validation failed", e);
        }
    }
}
```

### 6.2.1 合理的事务边界

public class OptimizedTransactionService {

### 6.2.2 事务嵌套处理
```java
@Service
public class NestedTransactionService {
    
    @Transactional
    public void createOrder(Order order) {
        // 创建订单
        orderRepository.save(order);
        
        try {
            // 嵌套事务处理订单详情
            orderDetailService.createOrderDetails(order.getId(), order.getItems());
        } catch (Exception e) {
            // 订单详情创建失败不影响订单创建

        }
    }
}

@Service
public class OrderDetailService {
    
    @Transactional(propagation = Propagation.NESTED)
    public void createOrderDetails(Long orderId, List<OrderItem> items) {
        // 创建订单详情
        // 如果失败，只回滚订单详情，不影响订单创建
        for (OrderItem item : items) {
            orderDetailRepository.save(new OrderDetail(orderId, item));
        }
    }
}
```

# 7 底层实现原理

## 7.1 回滚处理流程
```java
public class TransactionAspectSupport {
    
    protected void completeTransactionAfterThrowing(TransactionAttribute txAttr, 
                                                  TransactionStatus status, 
                                                  Throwable ex) {
        // 1. 判断是否需要回滚
        if (txAttr.rollbackOn(ex)) {
            // 2. 执行回滚
            doRollback(status);
        } else {
            // 3. 提交事务
            doCommit(status);
        }
    }
    
    private void doRollback(TransactionStatus status) {
        try {
            // 获取事务管理器
            PlatformTransactionManager tm = getTransactionManager();
            
            // 执行回滚
            tm.rollback(status);
        } catch (Exception ex) {
            // 记录回滚异常
            logger.error("Rollback exception", ex);
            throw ex;
        }
    }
}
```

## 7.2 关键类图
```
TransactionStatus (接口)
    └── DefaultTransactionStatus (默认实现)
        ├── 跟踪事务状态
        ├── 管理回滚标记
        └── 记录事务信息

TransactionAttribute (接口)
    ├── 定义回滚规则
    ├── 判断是否需要回滚
    └── 提供事务属性

RollbackRuleAttribute (回滚规则)
    ├── 定义回滚异常类型
    ├── 支持异常继承匹配
    └── 提供深度匹配算法

TransactionAspectSupport (事务切面支持)
    ├── 处理事务异常
    ├── 执行回滚操作
    └── 管理事务生命周期
```
