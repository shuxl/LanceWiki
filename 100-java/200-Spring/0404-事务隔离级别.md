# 2 事务隔离级别概念或介绍

## 2.1 什么是事务隔离级别
事务隔离级别（Transaction Isolation Level）定义了事务之间的隔离程度，即一个事务中的修改在另一个事务中的可见性。隔离级别越高，数据一致性越好，但并发性能越低。

## 2.2 隔离级别的作用
- **数据一致性保证**：防止并发事务之间的数据不一致
- **并发性能平衡**：在一致性和性能之间找到平衡点
- **并发问题控制**：解决脏读、不可重复读、幻读等问题
- **业务需求满足**：根据业务对数据一致性的要求选择合适的隔离级别

# 3 并发问题

## 3.1 脏读（Dirty Read）
一个事务读取了另一个未提交事务修改的数据。

### 3.1.1 问题描述
```
事务A：UPDATE account SET balance = balance - 100 WHERE id = 1;  -- 未提交
事务B：SELECT balance FROM account WHERE id = 1;  -- 读取到未提交的数据
事务A：ROLLBACK;  -- 回滚，数据恢复
```

### 3.1.2 影响
- 事务B读取到了不存在的数据
- 可能导致业务逻辑错误
- 数据不一致

## 3.2 不可重复读（Non-Repeatable Read）
一个事务内多次读取同一数据，但读取结果不一致。

### 3.2.1 问题描述
```
事务A：SELECT balance FROM account WHERE id = 1;  -- 读取到1000
事务B：UPDATE account SET balance = 2000 WHERE id = 1; COMMIT;
事务A：SELECT balance FROM account WHERE id = 1;  -- 读取到2000
```

### 3.2.2 影响
- 同一事务内数据不一致
- 可能影响业务逻辑判断
- 违反事务的隔离性

## 3.3 幻读（Phantom Read）
一个事务内多次查询同一范围的数据，但结果集不一致。

### 3.3.1 问题描述
```
事务A：SELECT COUNT(*) FROM orders WHERE user_id = 1;  -- 返回5
事务B：INSERT INTO orders (user_id, amount) VALUES (1, 100); COMMIT;
事务A：SELECT COUNT(*) FROM orders WHERE user_id = 1;  -- 返回6
```

### 3.3.2 影响
- 同一事务内结果集不一致
- 可能影响统计和报表
- 违反事务的隔离性

# 4 四种事务隔离级别

## 4.1 READ_UNCOMMITTED（读未提交）
最低的隔离级别，允许脏读、不可重复读、幻读。

### 4.1.1 特点
- 性能最好
- 数据一致性最差
- 很少使用

### 4.1.2 实现原理
```java
public class DataSourceTransactionManager {
    
    @Override
    protected void doBegin(Object transaction) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        // 设置隔离级别为读未提交
        con.setTransactionIsolation(Connection.TRANSACTION_READ_UNCOMMITTED);
        con.setAutoCommit(false);
    }
}
```

### 4.1.3 使用场景
- 对数据一致性要求不高的场景
- 只读操作占主导的应用
- 性能要求极高的场景

## 4.2 READ_COMMITTED（读已提交）
防止脏读，但允许不可重复读、幻读。

### 4.2.1 特点
- 大多数数据库的默认隔离级别
- 性能较好
- 防止脏读

### 4.2.2 实现原理
```java
public class DataSourceTransactionManager {
    
    @Override
    protected void doBegin(Object transaction) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        // 设置隔离级别为读已提交
        con.setTransactionIsolation(Connection.TRANSACTION_READ_COMMITTED);
        con.setAutoCommit(false);
    }
}
```

### 4.2.3 使用场景
- 大多数业务应用
- 对数据一致性有一定要求
- 需要平衡性能和一致性

## 4.3 REPEATABLE_READ（可重复读）
防止脏读、不可重复读，但允许幻读。

### 4.3.1 特点
- MySQL InnoDB的默认隔离级别
- 通过MVCC实现
- 防止不可重复读

### 4.3.2 实现原理
```java
public class DataSourceTransactionManager {

        Connection con = txObject.getConnectionHolder().getConnection();
        
        // 设置隔离级别为可重复读
        con.setTransactionIsolation(Connection.TRANSACTION_REPEATABLE_READ);

    }
}
```

### 4.3.3 MVCC实现
```java
// 简化的MVCC实现
public class MVCCManager {
    
    private Map<String, List<Version>> versions = new ConcurrentHashMap<>();
    
    public Object read(String key, long transactionId) {
        List<Version> versionList = versions.get(key);
        if (versionList == null) {
            return null;
        }
        
        // 找到小于等于当前事务ID的最新版本
        for (int i = versionList.size() - 1; i >= 0; i--) {
            Version version = versionList.get(i);
            if (version.getTransactionId() <= transactionId) {
                return version.getValue();
            }
        }
        
        return null;
    }
    
    public void write(String key, Object value, long transactionId) {
        List<Version> versionList = versions.computeIfAbsent(key, k -> new ArrayList<>());
        versionList.add(new Version(value, transactionId));
    }
}
```

### 4.3.4 使用场景
- 需要防止不可重复读的场景
- 对数据一致性要求较高的应用
- 金融、支付等关键业务

## 4.4 SERIALIZABLE（串行化）
最高的隔离级别，防止脏读、不可重复读、幻读。

### 4.4.1 特点
- 数据一致性最好
- 性能最差
- 通过锁机制实现

### 4.4.2 实现原理
```java
public class DataSourceTransactionManager {

    protected void doBegin(Object transaction) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        // 设置隔离级别为串行化
        con.setTransactionIsolation(Connection.TRANSACTION_SERIALIZABLE);
        con.setAutoCommit(false);
    }
}
```

### 4.4.3 锁机制实现
```java
public class LockManager {
    
    private Map<String, Lock> locks = new ConcurrentHashMap<>();
    
    public void acquireLock(String resource, LockType type, long transactionId) {
        Lock lock = locks.computeIfAbsent(resource, k -> new Lock());
        
        switch (type) {
            case SHARED:
                lock.acquireSharedLock(transactionId);
                break;
            case EXCLUSIVE:
                lock.acquireExclusiveLock(transactionId);
                break;
        }
    }
    
    public void releaseLock(String resource, long transactionId) {
        Lock lock = locks.get(resource);
        if (lock != null) {
            lock.releaseLock(transactionId);
        }
    }
}
```

### 4.4.4 使用场景
- 对数据一致性要求极高的场景
- 关键业务操作
- 报表生成等需要精确数据的场景

# 5 隔离级别的实现原理

## 5.1 数据库层面的实现

### 5.1.1 锁机制
```sql
-- 共享锁（读锁）
SELECT * FROM account WHERE id = 1 LOCK IN SHARE MODE;

-- 排他锁（写锁）
UPDATE account SET balance = 2000 WHERE id = 1;
```

### 5.1.2 MVCC（多版本并发控制）
```sql
-- 创建版本链
CREATE TABLE account (
    id INT PRIMARY KEY,
    balance DECIMAL(10,2),
    version_id BIGINT,
    created_at TIMESTAMP,
    deleted_at TIMESTAMP
);

-- 读取时选择合适版本
SELECT * FROM account 
WHERE id = 1 
  AND (deleted_at IS NULL OR deleted_at > ?)
  AND version_id <= ?;
```

### 5.1.3 快照隔离
```java
public class SnapshotIsolation {
    
    private Map<Long, Snapshot> snapshots = new ConcurrentHashMap<>();
    
    public Snapshot createSnapshot(long transactionId) {
        Snapshot snapshot = new Snapshot(transactionId, System.currentTimeMillis());
        snapshots.put(transactionId, snapshot);
        return snapshot;
    }
    
    public Object read(String key, long transactionId) {
        Snapshot snapshot = snapshots.get(transactionId);
        return snapshot.read(key);
    }
}
```

### 5.2.2 动态隔离级别
```java
public class DynamicIsolationTransactionManager extends DataSourceTransactionManager {
    
    @Override
    protected void doBegin(Object transaction) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        // 根据业务需求动态设置隔离级别
        IsolationLevel isolationLevel = getCurrentIsolationLevel();
        con.setTransactionIsolation(isolationLevel.getValue());
        con.setAutoCommit(false);
    }
    
    private IsolationLevel getCurrentIsolationLevel() {
        // 根据当前业务上下文决定隔离级别
        String businessType = getCurrentBusinessType();
        return IsolationLevelResolver.resolve(businessType);
    }
}
```

# 6 隔离级别的选择策略

## 6.1 选择依据
1. **数据一致性要求**：业务对数据一致性的敏感程度
2. **并发性能要求**：系统的并发访问量
3. **业务场景特点**：读多写少还是写多读少
4. **数据库特性**：不同数据库的默认隔离级别

## 6.2 选择指南

### 6.2.1 高一致性场景
- **金融交易**：SERIALIZABLE
- **支付处理**：REPEATABLE_READ
- **库存管理**：REPEATABLE_READ

### 6.2.2 高并发场景
- **用户查询**：READ_COMMITTED
- **报表统计**：READ_COMMITTED
- **缓存更新**：READ_UNCOMMITTED

### 6.2.3 平衡场景
- **一般业务**：READ_COMMITTED
- **订单处理**：REPEATABLE_READ
- **用户管理**：READ_COMMITTED

## 6.3 性能考虑

### 6.3.1 隔离级别对性能的影响
```
性能排序（从高到低）：
READ_UNCOMMITTED > READ_COMMITTED > REPEATABLE_READ > SERIALIZABLE

一致性排序（从高到低）：
SERIALIZABLE > REPEATABLE_READ > READ_COMMITTED > READ_UNCOMMITTED
```

### 6.3.2 优化策略
```java
@Service
public class OptimizedTransactionService {
    
    @Transactional(isolation = Isolation.READ_COMMITTED)
    public void processOrder(Order order) {
        // 主要业务逻辑使用较低隔离级别
        orderRepository.save(order);
        
        // 关键操作使用较高隔离级别
        processPayment(order.getPayment());
    }
    
    @Transactional(isolation = Isolation.REPEATABLE_READ)
    public void processPayment(Payment payment) {
        // 支付处理需要更高的一致性
        accountService.updateBalance(payment.getAccountId(), payment.getAmount());
        paymentRepository.save(payment);
    }
}
```

# 7 底层实现原理

## 7.1 事务隔离级别处理流程
```java
public class TransactionAspectSupport {
    
    protected TransactionStatus startTransaction(TransactionDefinition definition, Object transaction) {
        // 1. 获取隔离级别
        int isolationLevel = definition.getIsolationLevel();
        
        // 2. 设置数据库隔离级别
        if (isolationLevel != TransactionDefinition.ISOLATION_DEFAULT) {
            setTransactionIsolation(transaction, isolationLevel);
        }
        
        // 3. 开始事务
        doBegin(transaction);
        
        return newTransactionStatus(definition, transaction, true);
    }
    
    private void setTransactionIsolation(Object transaction, int isolationLevel) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        try {
            con.setTransactionIsolation(isolationLevel);
        } catch (SQLException ex) {
            throw new TransactionSystemException("Could not set transaction isolation", ex);
        }
    }
}
```

## 7.2 关键类图
```
TransactionDefinition (接口)
    ├── ISOLATION_DEFAULT (默认隔离级别)
    ├── ISOLATION_READ_UNCOMMITTED (读未提交)

    ├── ISOLATION_REPEATABLE_READ (可重复读)
    └── ISOLATION_SERIALIZABLE (串行化)

PlatformTransactionManager (接口)

LockManager (锁管理器)
    ├── 管理共享锁

MVCCManager (多版本并发控制)
    ├── 管理版本链
    ├── 处理快照隔离
    └── 提供一致性读取
```
