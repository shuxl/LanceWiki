
# 1 泛型基础
- 泛型类、泛型接口、泛型方法的基本语法
- 泛型的声明与使用
- 泛型的类型参数可以是任意引用类型，不能是基本类型

---

# 2 类型擦除（Type Erasure）
- Java 泛型在编译后会进行类型擦除，所有泛型参数都会被替换为 Object 或限定类型
- 运行时无法获取泛型的实际类型参数（即：`List<String>` 和 `List<Integer>` 运行时是同一个类）
- 不能用 `instanceof` 判断带泛型的类型，如 `if (list instanceof List<String>)` 是非法的
- 反射获取泛型参数时需用 `Type`，但有局限

> **面试提醒：** 类型擦除导致的运行时类型信息丢失，是很多泛型相关 bug 的根源。

---

# 3 泛型的边界（Bounded Type Parameters）
- 上界：`<T extends Number>`，T 必须是 Number 或其子类
- 下界：只能用于通配符，如 `<? super Integer>`
- 多重边界：`<T extends InterfaceA & InterfaceB>`

---

# 4 通配符（Wildcard）
- 无界通配符：`<?>`，表示任意类型
- 上界通配符：`<? extends Number>`，只能读取，不能写入（除了 null）
- 下界通配符：`<? super Integer>`，可以写入 Integer 及其子类
- PECS 原则：Producer Extends, Consumer Super
	- **如果你需要“生产”数据（从集合中读取），就使用 extends。**
	- **如果你需要“消费”数据（往集合中写入），就使用 super。**

> **面试提醒：** 通配符和泛型方法的区别、PECS 原则是高频考点。

---

# 5 泛型方法
- 方法上声明泛型：`<T> T copy(T obj)`
- 静态方法也可以声明泛型
- 泛型方法与泛型类无关

---

# 6 泛型数组
- 不能直接创建泛型数组：`new T[]` 非法
- 解决方案：用 `Object[]` 强转，或用 `Array.newInstance()`
- 泛型数组的类型安全问题

---

# 7 泛型与继承
- `List<String>` 不是 `List<Object>` 的子类（泛型不具备协变性）
- 但数组是协变的：`String[]` 是 `Object[]` 的子类
- 通配符可实现一定的协变/逆变

---

# 8 泛型与接口
- 接口可以定义泛型参数
- 实现类可以保留泛型或指定具体类型

```java
interface Generator<T> { T next(); }
class StringGenerator implements Generator<String> { public String next() { return "abc"; } }
```

---

# 9 泛型与反射
- 反射获取泛型参数时，需用 `getGenericSuperclass()` 或 `getGenericInterfaces()`
- 但类型擦除后，部分信息不可得

---

# 10 泛型的局限性
- 不能用基本类型作为泛型参数（如 `List<int>` 非法）
- 不能创建泛型数组
- 不能实例化泛型类型参数（如 `new T()` 非法）
- 静态成员不能引用类的泛型参数

---

# 11 类型推断（Type Inference）
- Java 7 以后支持菱形语法：`List<String> list = new ArrayList<>();`
- 方法调用时可自动推断类型参数

---

# 12 泛型与集合
- 集合类广泛使用泛型，保证类型安全
- 使用通配符时注意读写限制

---

# 13 泛型最佳实践
- 尽量使用泛型，避免原生类型（raw type）
- 合理使用通配符，遵循 PECS 原则
- 不要滥用泛型，简单场景下无需泛型
- 避免类型转换警告

---

# 14 面试常见陷阱&易错点
- 泛型类型擦除导致的类型转换异常
- 通配符使用不当导致编译错误
- 泛型数组的类型安全问题
- 泛型与反射结合时类型信息丢失
- 泛型方法与泛型类的混淆
- 泛型与协变/逆变的理解误区

---
