MySQL 开发人员迁移到 OceanBase 注意事项清单

（基于 MySQL 5.7 协议兼容模式）

  

### **1. 数据类型与语法**

|**项目**|**MySQL**|**OceanBase MySQL 模式**|**风险**|**建议做法**|
|---|---|---|---|---|
|数据类型|全部 MySQL 5.7 类型|大部分兼容，但部分范围不同|超过范围时报错或截断|迁移前用 information_schema.columns 检查长度与精度|
|自增主键|连续递增|分布式生成，可能不连续|依赖连续 ID 的业务会出错|业务不要依赖连续性，可用业务 ID 生成器|
|ENUM / SET|支持|部分版本不支持|SQL 执行失败|迁移前改成 VARCHAR + CHECK 约束|
|JSON|MySQL 原生 JSON 类型|部分版本缺失原生 JSON|JSON 查询异常|改用 TEXT 存储并用应用层解析|

---

### **2. 索引与主键**

|**项目**|**MySQL**|**OceanBase MySQL 模式**|**风险**|**建议做法**|
|---|---|---|---|---|
|主键分区|主键仅存储本表|主键同时是分区键（默认 HASH）|查询未命中分区键会变慢|表设计时考虑主查询字段作为分区键|
|二级索引|全局唯一索引|有本地索引和全局索引两种|跨分区唯一索引性能差|避免大范围唯一约束，改为业务检查|
|索引数量|较多影响写性能|分布式维护代价更高|写入延迟增加|控制索引数量，必要时分表|

---

### **3. SQL 特性差异**

|**项目**|**MySQL**|**OceanBase MySQL 模式**|**风险**|**建议做法**|
|---|---|---|---|---|
|分区表|不常用|默认分区存储|SQL 路由错误导致慢查询|了解分区策略，常用条件加分区键|
|JOIN|本地执行|跨分区需数据重分发|大表 JOIN 性能差|优先本地 JOIN，减少跨分区|
|DDL|元数据单机更新|全局同步 DDL|频繁 DDL 慢且锁表时间长|尽量在低峰期做 DDL|
|函数|全部支持|部分差异|结果不同|对日期/时间函数特别测试|
|LIMIT|支持|支持|大数据分页性能差|大分页改用游标或主键范围查询|

---

### **4. 事务与锁**

|**项目**|**MySQL**|**OceanBase MySQL 模式**|**风险**|**建议做法**|
|---|---|---|---|---|
|隔离级别|默认 RR|默认 RC|幻读处理差异|确认事务隔离级别需求|
|跨分区事务|单机事务|分布式 2PC|延迟增加|避免跨分区更新|
|锁类型|表/行锁|表/行锁（分布式）|锁冲突范围更大|减少热点数据更新|

---

### **5. 开发与调优**

|**项目**|**MySQL**|**OceanBase MySQL 模式**|**风险**|**建议做法**|
|---|---|---|---|---|
|JDBC 驱动|mysql-connector-java|兼容 MySQL 驱动|无|用 MySQL 8.x 驱动，URL 配时区|
|SQL 优化|EXPLAIN|EXPLAIN EXTENDED|不了解执行计划会误判性能|学会看 OB 的分区路由和分布式执行节点|
|慢查询日志|单机慢日志|分布式慢日志|慢查询分析不全|用 OCP 或系统表收集全局慢查询|
|批量写入|INSERT 多条|分布式事务开销大|批量写变慢|合并成批量事务减少 commit 次数|

---

### **6. 运维与监控**

| **项目** | **MySQL**          | **OceanBase MySQL 模式** | **风险**         | **建议做法**       |
| ------ | ------------------ | ---------------------- | -------------- | -------------- |
| 系统表    | information_schema | oceanbase、gv$ 系统表      | 运维工具不兼容        | 迁移监控脚本到 OB 系统表 |
| 主从复制   | 主从复制协议             | 多副本 Paxos              | 无法用 MySQL 主从监控 | 学习 OB 副本状态监控方法 |
| 扩容     | 需额外组件              | 水平扩展内置支持               | 扩容需重新分布数据      | 低峰期扩容，观察负载均衡过程 |

---

### **迁移建议流程**

1. **评估差异**
    
    - 用 OceanBase 提供的 **obdiag / obcomp** 工具扫描 MySQL 数据库，生成兼容性报告。
        
    
2. **改造 DDL/SQL**
    
    - 重点检查数据类型、分区键、跨分区 SQL。
        
    
3. **小流量验证**
    
    - 先做影子库/双写验证，监控 SQL 性能。
        
    
4. **全量迁移**
    
    - 数据导入可用 obloader 或 MySQL Dumper + obloader。
        
    
5. **上线监控**
    
    - 启用 OceanBase OCP 监控、慢 SQL 分析、执行计划跟踪。
