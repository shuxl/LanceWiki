​**推荐系统中的数据分布**​

- ● ​**推荐系统中的一次用户请求就是一个样本**​  
    ● 数据结构: 用户与App互动构成“数据点”，包含:
    - 用户: 年龄、性别、地域、历史购买记录等。
    - 物品: 商品类别、品牌、价格、被浏览次数等。
    - 场景: 时间、页面行为。  
        ● ​**单个用户请求(样本)​**: 如用户点击手机，样本信息有限。
- ● ​**数据分布: 从单个样本到整体流量**​  
    ● 聚合用户请求形成数据分布，学习规律提升推荐效果。  
    ● ​**热门分布(Popularity Distribution)​**:
    - 现象: 极少数商品占多数流量；大量商品流量极少。
    - 分布形态: 长尾分布(Long-tail Distribution) - 头部(热门) vs 尾部(冷门)。  
        ● ​**应用意义: 冷启动中的“热门推荐”​**​
    - 新用户时，基于热门分布推荐: 不依赖用户画像、点击率高、帮助接触主流内容。
- ● ​**用户行为分布(User Behavior Distribution)​**​  
    ● 现象: 特定群体行为分布（如“年轻女性”晚间购买护肤品和零食）。  
    ● 分布形态: 时间上正态分布或多峰分布，品类上偏好分布。  
    ● ​**应用价值**: 实现时段+品类双重匹配，提升点击率与转化率。

​**为什么分布重要?​**​

- ● 推荐系统目的: 不是“记住”用户点过什么，而是“预测”用户接下来会点什么。
- ● 核心问题: 分布建模问题（用户偏好建模、群体差异建模）。
- ● 分布不是固定的: 行为模式随环境变化（如世界杯、春节）。
- ● ​**独立同分布假设(i.i.d.)​**:  
    ● 假设: “样本是从同一个分布中独立采样得到的。”  
    ● 关键问题:
    - 什么是“独立”与“同分布”?
    - i.i.d.假设何时成立? 何时失效?
    - 违反i.i.d.会带来什么问题? 如何检测与修复?

​**违反i.i.d.的案例: AI模型上线后出错**​

- ● 语音助手“听不懂你说话”:  
    ● 训练数据: 标准普通话、中年人群、安静环境。  
    ● 真实使用: 上海话、嘈杂地铁、嚼口香糖。  
    ● 结果: 误听指令（如“帮我导航到最近的咖啡店”误为“打开天气预报”）。
- ● ​**背后问题: 训练数据和使用数据不一致**​  
    ● 模型只能学习“见过”的数据，未来情况差异大时“考砸”。
- ● ​**独立同分布(i.i.d.)解释**:  
    ● 同分布: 数据生成机制一致（如训练用正式英语，测试用网络口语）。
    - 案例: 广告推荐模型在一线城市训练，三四线城市部署后效果骤降。  
        ● 独立: 数据生成互不影响（如并发用户数预测，标签依赖所有用户行为）。

​**数据集划分方法**​

- ● ​**核心原则**:  
    ● 样本随机抽取，满足i.i.d.假设。  
    ● 保证训练过程看不到“未来”数据，避免信息泄露。  
    ● 各子集代表整体数据分布。
- ● ​**策略一: 简单留出法(Simple Hold-Out)​**​  
    ● 核心思想: 一次性的快速摸底考。  
    ● 分工:
    - 训练集(Training Set): 教科书与练习册（学习知识）。
    - 验证集(Validation Set): 模拟考试（校准超参数）。
    - 测试集(Test Set): 最终高考（公正评估）。  
        ● 痛点: 评估结果的“偶然性”（单次划分不稳定）。
- ● ​**策略二: K-折交叉验证(K-Fold Cross-Validation)​**​  
    ● 核心思想: 多轮会考（全员参与）。  
    ● 流程（K=5例）:
    1. 数据打乱。
    2. 切分K个折(folds)。
    3. 循环训练验证（每轮一折验证，剩余训练）。
    4. 平均得分作为最终评估（更稳健）。
- ● ​**策略三: 分层抽样(Stratified Sampling)​**​  
    ● 核心思想: 确保子集“成分”与整体一致（增强补丁）。  
    ● 问题场景: 数据分布不均（如信用卡欺诈检测，99%正常交易 vs 1%欺诈）。  
    ● ​**错误示范（简单随机抽样）​**: 测试集可能全为正常交易，无法评估欺诈识别能力。  
    ● ​**正确做法（分层抽样）​**: 按类别等比例抽取（如正常交易抽10% -> 990笔，欺诈抽10% -> 10笔）。

​**练习部分**​

​**数据分布小结**​

- ● 科学数据集划分: 影响模型评估公正性和泛化能力。
- ● 独立同分布假设(i.i.d.): 训练和评估的理论前提。
- ● 三大方法适用场景:  
    ● 简单留出法: 大数据，快捷高效。

​**从物理世界到数学空间: 线性代数与数据表示**​

- ● 核心思想: 用向量描述物理概念（如力、位置），并创造“语义空间”。
- ● ​**语义空间(Semantic Space)​**:  
    ● 定义坐标轴（如X轴: 甜度, Y轴: 体积）。  
    ● 映射实体:

| 水果(Fruit)      | 属性描述(Attributes) | 空间坐标(Vector) |
| -------------- | ---------------- | ------------ |
| 草莓(Strawberry) | 甜度很高(9),体积很小(2)  | (9,2)        |
| 西瓜(Watermelon) | 甜度中等(6),体积巨大(9)  | (6,9)        |
| 柠檬(Lemon)      | 甜度极低(1),体积较小(3)  | (1,3)        |
| 苹果(Apple)      | 甜度、体积都适中(7,6)    | (7,6)        |


- ● ​**空间关系: 距离与方向**​  
    ● 欧几里得距离: 衡量相似度（如苹果(7,6)和西瓜(6,9)距离近→相似）。  
    ● 余弦相似度（进阶版）: 衡量向量方向一致性（本质相似度）。
    - 公式: Similarity=cos(θ)=∥A∥∥B∥A⋅B​
    - 解读: 值接近1（非常相似），接近0（毫不相关），接近-1（意义对立）。
- ● ​**智能应用: 向量检索完成“智能推荐”​**​  
    ● 用户请求: “推荐和苹果最像的水果”。  
    ● AI执行步骤:
    1. 定位查询目标（V_apple=(7,6)）。
    2. 全库计算余弦相似度（如西瓜: 0.95, 草莓: 0.6, 柠檬: 0.15）。
    3. 排序生成答案: “和苹果最相似的水果是西瓜!”。  
        ● 应用场景: 以图搜图、推荐系统、智能问答。
- ● ​**从2维到N维: 真实AI世界**​  
    ● 进化1: 维度暴增（数百至上千维）。  
    ● 进化2: 意义自动学习（神经网络发现抽象维度，如“性别”方向）。

​**新篇章: 微积分赋予AI“学习”能力的引擎**​

- ● ​**承前启后**:  
    ● 线性代数将数据向量化，但需建模向量间“关系”。  
    ● AI核心问题: 如房价预测、图像分类、情感分析。
- ● ​**第二步: 用数学表达式建模关系**​  
    ● 建模: 假设函数（如线性模型: 预测价格 = w1·面积 + w2·房龄 + w3·卧室数 + b）。  
    ● AI学习本质: 找到最佳参数（w1, w2, w3, b），使预测误差最小。
- ● ​**核心引擎: 梯度下降法**​  
    ● 自动化寻优策略（计算机执行）:
    
    ```
    for epoch in range(epochs):
        # 1. 预测: y_predicted = w * X + b
        # 2. 计算梯度: 
        dw = (-2/n) * sum(X * (y - y_predicted))
        db = (-2/n) * sum(y - y_predicted)
        # 3. 更新参数:
        w = w - learning_rate * dw
        b = b - learning_rate * db
    ```
    
    ● 梯度: 误差下降最快方向（微积分核心）。
- ● ​**理解可微性: AI模型设计的“隐形铁律”​**​  
    ● 逻辑链条: 梯度下降法需梯度 → 梯度依赖导数 → 导数要求函数平滑连续（可微）。  
    ● 设计约束: 整个数学表达式必须“端到端可微”（如CNN、RNN、LSTM、Transformer的创新基础）。
- ● ​**AI“学习”本质回顾**:  
    ● 建模(Modeling): 用可微函数拟合世界关系。  
    ● 优化(Optimization): 梯度下降法自动求解最优解。  
    ● 前提(Prerequisite): 可微性是自动化过程的保证。

​**思考题**​

- ● 现实世界粗糙不完美: 如果真实关系不可微（如价格阶梯跳变、规则引擎硬决策），怎么办?
- ● 当“山路”不平滑，梯度下降法失灵: 还有别的“下山”方法吗?
