# 1. 底层实现原理
- **ArrayList**：基于动态数组实现，支持随机访问，内存连续。
- **LinkedList**：基于双向链表实现，节点分散存储，每个节点包含前后指针。

---

# 2. 常见操作的时间复杂度
| 操作         | ArrayList      | LinkedList     |
| ------------ | -------------- | -------------- |
| 随机访问get  | O(1)           | O(n)           |
| 插入add尾部  | O(1)（均摊）   | O(1)           |
| 插入add中间  | O(n)           | O(n)           |
| 删除remove尾 | O(1)           | O(1)           |
| 删除remove中 | O(n)           | O(n)           |
| 插入头部     | O(n)           | O(1)           |

> **面试提醒：** ArrayList 只有在尾部插入/删除时才是 O(1)，中间操作都要移动元素。

---

# 3. 适用场景
- **ArrayList**：
  - 需要频繁随机访问元素
  - 读多写少，插入/删除主要在尾部
- **LinkedList**：
  - 需要频繁在头部或中间插入/删除元素
  - 作为队列、双端队列、栈等数据结构

---

# 4. 面试易错点与陷阱
- 误以为 LinkedList 所有插入/删除都是 O(1)，实际上只有头尾是 O(1)，中间仍需遍历
- 误用 LinkedList 进行大量随机访问，性能极差
- ArrayList 扩容机制导致插入大量数据时有性能抖动
- LinkedList 节点对象多，内存占用大，频繁GC

---

# 5. 源码关注点
- ArrayList 的扩容机制（grow 方法，1.5倍扩容）
- LinkedList 的节点结构（Node 内部类，prev/next 指针）
- add/remove 的实现细节

---

# 6. 实际开发建议
- 绝大多数场景优先用 ArrayList，除非有明确的链表需求
- 需要频繁头部插入/删除、实现队列/栈时可用 LinkedList
- 注意集合的线程安全问题，必要时用并发包下的集合

---

> **总结：**
> - ArrayList 适合读多写少、随机访问多的场景
> - LinkedList 适合频繁头部操作、实现特殊数据结构
> - 面试时要结合底层原理和实际场景分析选择
