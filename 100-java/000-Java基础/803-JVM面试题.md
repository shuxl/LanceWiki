# 2 JVM内存结构

## 2.1 JVM内存结构包括哪些部分？

**JVM内存结构：**
- **堆（Heap）**：存储对象实例，所有线程共享
- **方法区（Method Area）**：存储类信息、常量、静态变量
- **虚拟机栈（VM Stack）**：存储局部变量、操作数栈、方法出口
- **本地方法栈（Native Method Stack）**：为本地方法服务
- **程序计数器（Program Counter Register）**：当前线程执行的字节码行号

**详细说明：**
```java
// 堆内存分配示例
public class HeapExample {
    public static void main(String[] args) {
        // 对象分配在堆中
        Object obj = new Object();
        
        // 大对象可能直接进入老年代
        byte[] bigArray = new byte[4 * 1024 * 1024]; // 4MB
    }
}
```

## 2.2 堆内存的年轻代和老年代是如何划分的？

**堆内存划分：**
- **年轻代（Young Generation）**：1/3堆空间
  - Eden区：8/10年轻代空间
  - Survivor区：2/10年轻代空间（From和To各占1/10）
- **老年代（Old Generation）**：2/3堆空间

**对象分配过程：**
1. 新对象优先分配在Eden区
2. Eden区满时触发Minor GC
3. 存活对象移动到Survivor区
4. 经过多次Minor GC后进入老年代

## 2.3 什么是对象头？对象头包含哪些信息？

**对象头结构：**
- **Mark Word**：8字节，存储对象运行时数据
- **Klass Pointer**：4字节（32位）或8字节（64位），指向类元数据

**Mark Word内容：**
- 哈希码
- GC分代年龄
- 锁状态标志
- 线程持有的锁
- 偏向线程ID
- 偏向时间戳

```java
// 对象头示例
public class ObjectHeaderExample {
    public static void main(String[] args) {
        Object obj = new Object();
        // 对象头在对象创建时自动生成
        // 包含Mark Word和Klass Pointer
    }
}
```

# 3 垃圾回收机制

## 3.1 什么是垃圾回收？如何判断对象是否可回收？

**垃圾回收：** 自动回收不再使用的内存空间。

**判断对象可回收的方法：**
1. **引用计数法**：记录对象被引用次数，为0时回收
2. **可达性分析**：从GC Roots开始，无法到达的对象可回收

**GC Roots包括：**
- 虚拟机栈中引用的对象
- 方法区中静态属性引用的对象
- 方法区中常量引用的对象
- 本地方法栈中JNI引用的对象

## 3.2 垃圾回收算法有哪些？各有什么特点？

**主要算法：**

**1. 标记-清除算法（Mark-Sweep）：**
- 标记阶段：标记所有需要回收的对象
- 清除阶段：回收被标记的对象
- 缺点：产生内存碎片

**2. 复制算法（Copying）：**
- 将内存分为两块，每次只使用一块
- 将存活对象复制到另一块，清理当前块
- 优点：效率高，无内存碎片
- 缺点：内存利用率低

**3. 标记-整理算法（Mark-Compact）：**
- 标记阶段：标记所有需要回收的对象
- 整理阶段：将存活对象向一端移动
- 优点：无内存碎片
- 缺点：效率较低

**4. 分代收集算法：**
- 年轻代：复制算法
- 老年代：标记-整理或标记-清除算法

## 3.3 常见的垃圾收集器有哪些？

**年轻代收集器：**
- **Serial**：单线程，STW时间长
- **ParNew**：多线程版本的Serial
- **Parallel Scavenge**：吞吐量优先

**老年代收集器：**
- **Serial Old**：单线程，标记-整理算法
- **Parallel Old**：多线程版本的Serial Old
- **CMS**：并发收集，低延迟
- **G1**：区域化内存布局，可预测的停顿时间

**组合使用：**
```bash
常用组合
-XX:+UseSerialGC                    # Serial + Serial Old
-XX:+UseParNewGC                    # ParNew + Serial Old
-XX:+UseParallelGC                  # Parallel Scavenge + Parallel Old
-XX:+UseConcMarkSweepGC            # ParNew + CMS
-XX:+UseG1GC                       # G1收集器
```

# 4 类加载机制

## 4.1 类加载的过程包括哪些阶段？

**类加载过程：**
1. **加载（Loading）**：加载字节码文件到内存
2. **验证（Verification）**：验证字节码的正确性
3. **准备（Preparation）**：为静态变量分配内存并设置初始值
4. **解析（Resolution）**：将符号引用转换为直接引用
5. **初始化（Initialization）**：执行静态代码块和静态变量赋值
6. **使用（Using）**：使用类
7. **卸载（Unloading）**：类被卸载

```java
// 类加载示例
public class ClassLoadingExample {
    static {
        System.out.println("静态代码块执行");
    }
    
    private static int staticVar = 100;
    
    public static void main(String[] args) {
        System.out.println("类已加载并初始化");
    }
}
```

## 4.2 什么是双亲委派模型？为什么要使用双亲委派？

**双亲委派模型：**
- 类加载器收到加载请求时，先委托给父加载器
- 父加载器无法加载时，才由自己加载
- 形成层次结构：Bootstrap → Extension → Application → 自定义

**优势：**
- 避免重复加载
- 保证核心类库安全
- 保证类的一致性

```java
// 双亲委派示例
public class ClassLoaderExample {
    public static void main(String[] args) {
        // 获取类加载器
        ClassLoader loader = ClassLoaderExample.class.getClassLoader();
        System.out.println("当前类加载器: " + loader);
        System.out.println("父加载器: " + loader.getParent());
    }
}
```

## 4.3 如何破坏双亲委派模型？

**破坏方式：**
1. **重写loadClass方法**：直接加载类，不委托父加载器
2. **线程上下文类加载器**：使用Thread.currentThread().getContextClassLoader()
3. **OSGi**：模块化框架，每个模块有自己的类加载器

```java
// 自定义类加载器示例
public class CustomClassLoader extends ClassLoader {
    @Override
    protected Class<?> loadClass(String name, boolean resolve) 
            throws ClassNotFoundException {
        // 自定义加载逻辑，可能破坏双亲委派
        return super.loadClass(name, resolve);
    }
}
```

# 5 字节码和JIT编译

## 5.1 什么是字节码？字节码指令有哪些类型？

**字节码：** Java源代码编译后的中间代码，JVM执行的指令集。

**主要指令类型：**
- **加载和存储指令**：load、store
- **运算指令**：add、sub、mul、div
- **类型转换指令**：i2l、f2d
- **对象创建和访问指令**：new、getfield、putfield
- **操作数栈管理指令**：pop、dup
- **控制转移指令**：ifeq、goto
- **方法调用和返回指令**：invokevirtual、return

```java
// 字节码示例
public class BytecodeExample {
    public int add(int a, int b) {
        return a + b;
    }
}

// 对应的字节码（简化）
// iload_1    // 加载参数a
// iload_2    // 加载参数b
// iadd       // 执行加法
// ireturn    // 返回结果
```

## 5.2 什么是JIT编译？JIT编译的优化技术有哪些？

**JIT编译：** Just-In-Time编译，将热点字节码编译为本地机器码。

**优化技术：**
1. **方法内联**：将小方法调用替换为方法体
2. **逃逸分析**：分析对象作用域，进行栈分配
3. **锁消除**：消除不必要的锁
4. **锁粗化**：合并多个锁操作
5. **循环展开**：展开循环减少循环开销

```java
// JIT优化示例
public class JITExample {
    public static void main(String[] args) {
        // 热点代码，会被JIT编译
        for (int i = 0; i < 10000; i++) {
            hotMethod();
        }
    }
    
    private static void hotMethod() {
        // 可能被内联优化
        int result = 1 + 2;
    }
}
```

# 6 性能调优和监控

## 6.1 JVM性能调优的主要参数有哪些？

**堆内存参数：**
```bash
-Xms2048m                    # 初始堆大小
-Xmx2048m                    # 最大堆大小
-Xmn512m                     # 年轻代大小
-XX:NewRatio=3               # 老年代与年轻代比例
-XX:SurvivorRatio=8          # Eden与Survivor比例
```

**垃圾回收参数：**
```bash
-XX:+UseG1GC                 # 使用G1收集器
-XX:MaxGCPauseMillis=200     # 最大GC停顿时间
-XX:G1HeapRegionSize=16m     # G1区域大小
-XX:+PrintGCDetails          # 打印GC详细信息
```

**其他参数：**
```bash
-XX:+HeapDumpOnOutOfMemoryError  # OOM时生成堆转储文件
-XX:HeapDumpPath=/path/to/dump   # 堆转储文件路径
-XX:+PrintGCApplicationStoppedTime  # 打印应用停顿时间
```

## 6.2 如何监控JVM性能？

**监控工具：**
1. **jps**：查看Java进程
2. **jstat**：查看JVM统计信息
3. **jmap**：生成堆转储文件
4. **jstack**：生成线程转储文件
5. **jconsole**：图形化监控工具
6. **VisualVM**：综合监控工具
7. **JProfiler**：商业性能分析工具

**常用命令：**
```bash
查看进程
jps -l

查看GC统计
jstat -gc <pid> 1000 10

生成堆转储
jmap -dump:format=b,file=heap.hprof <pid>

查看线程状态
jstack <pid>
```

## 6.3 常见的JVM问题有哪些？如何排查？

**常见问题：**

**1. 内存泄漏：**
- 现象：堆内存持续增长，频繁Full GC
- 排查：使用jmap生成堆转储，分析对象引用链

**2. 频繁GC：**
- 现象：GC频率过高，影响应用性能
- 排查：调整堆大小、优化对象创建

**3. 线程死锁：**
- 现象：应用无响应，CPU使用率低
- 排查：使用jstack查看线程状态

**4. 类加载问题：**
- 现象：ClassNotFoundException或NoClassDefFoundError
- 排查：检查类路径、类加载器

```java
// 内存泄漏示例
public class MemoryLeakExample {
    private static List<Object> list = new ArrayList<>();
    
    public static void addObject(Object obj) {
        list.add(obj); // 可能导致内存泄漏
    }
}
```

## 6.4 如何分析堆转储文件？

**分析工具：**
1. **MAT（Memory Analyzer Tool）**：Eclipse插件
2. **JProfiler**：商业工具
3. **VisualVM**：JDK自带工具

**分析步骤：**
1. 生成堆转储文件
2. 使用分析工具打开
3. 查看内存占用情况
4. 分析对象引用关系
5. 找出内存泄漏原因

```bash
生成堆转储
jmap -dump:format=b,file=heap.hprof <pid>

使用MAT分析（需要安装Eclipse MAT插件）
或者使用VisualVM打开heap.hprof文件
```
