# Langfuse Docker 本地搭建注意要点

## 概述

本文档列出了在本地环境搭建 Langfuse Docker 环境时需要注意的关键要点，帮助避免常见问题并确保顺利部署。

## 一、准备阶段注意事项

### 1. 版本选择

- **版本确认**：Langfuse 有 v2 和 v3 两个主要版本，需要根据需求选择合适的版本
  - v2 版本的安全更新支持可能截止到 Q1 2025，建议新项目使用 v3
  - 不同版本的 docker-compose.yml 配置和环境变量要求可能不同
  - 建议查看官方文档确认当前推荐版本

### 2. 环境依赖检查

- **Docker 环境**：
  - 确保已安装 Docker Desktop 或 Docker Engine
  - 确保已安装 Docker Compose（新版本使用 `docker compose`，旧版本使用 `docker-compose`）
  - 检查 Docker 服务是否正常运行：`docker info`
  
- **系统资源**：
  - **最低配置**：2 核 CPU + 4 GB 内存（仅用于测试）
  - **推荐配置**：4 核 CPU + 8 GB 内存以上
  - **磁盘空间**：预留足够空间，ClickHouse 数据存储会占用较大空间
  - 确保 Docker Desktop 的资源分配足够（Mac 上可在 Docker Desktop 设置中调整）

### 3. 端口占用检查

- Langfuse 默认使用端口 **3000**（Web 界面）
- 检查端口是否被占用：`lsof -i :3000`
- 如果端口被占用，需要修改 docker-compose.yml 中的端口映射

## 二、环境变量配置要点

### 1. 必填环境变量（核心配置）

#### 数据库配置
- **`DATABASE_URL`**：PostgreSQL 数据库连接字符串
  - 格式：`postgresql://用户名:密码@主机:端口/数据库名`
  - 示例：`postgresql://langfuse:password@postgres:5432/langfuse`
  - ⚠️ **注意**：确保数据库容器先启动，或使用外部数据库

#### ClickHouse 配置（用于 OLAP 存储）
- **`CLICKHOUSE_URL`**：ClickHouse 连接地址
- **`CLICKHOUSE_USER`**：ClickHouse 用户名
- **`CLICKHOUSE_PASSWORD`**：ClickHouse 密码
- ⚠️ **注意**：ClickHouse 是必需的，不能省略

#### Redis 配置（用于队列和缓存）
- **`REDIS_CONNECTION_STRING`** 或 **`REDIS_HOST`**：Redis 连接配置
- 格式：`redis://用户名:密码@主机:端口` 或 `redis://主机:端口`
- ⚠️ **注意**：确保 Redis 容器正常运行

#### 认证和安全配置
- **`NEXTAUTH_URL`**：前端访问地址和认证回调 URL
  - 本地开发：`http://localhost:3000`
  - ⚠️ **注意**：必须与实际访问地址一致，否则认证会失败
  
- **`NEXTAUTH_SECRET`**：Session/Token 签名密钥
  - ⚠️ **重要**：必须使用随机生成的强密钥，不能使用默认值
  - 生成方式：`openssl rand -base64 32`
  
- **`SALT`**：API key 哈希盐值
  - ⚠️ **重要**：必须使用随机生成的强密钥
  - 生成方式：`openssl rand -base64 32`
  
- **`ENCRYPTION_KEY`**：敏感数据加密密钥
  - ⚠️ **重要**：必须使用随机生成的强密钥（32 字节）
  - 生成方式：`openssl rand -base64 32`

### 2. 可选但推荐的配置

- **`HOSTNAME`**：设置为 `0.0.0.0` 允许外部访问（如果需要从其他机器访问）
- **`LANGFUSE_CSP_ENFORCE_HTTPS`**：是否强制 HTTPS（生产环境建议开启）
- **`NODE_OPTIONS`**：Node.js 内存限制，例如 `--max-old-space-size=4096`（避免内存不足）

### 3. 存储配置（可选）

如果启用 Blob/Media 存储，需要配置 S3 或兼容方案（如 MinIO）：
- **`S3_ACCESS_KEY_ID`**：S3 访问密钥 ID
- **`S3_SECRET_ACCESS_KEY`**：S3 访问密钥
- **`S3_BUCKET_NAME`**：S3 存储桶名称
- **`S3_ENDPOINT`**：S3 端点地址（使用 MinIO 时需要）

### 4. 环境变量配置方式

- **方式1**：使用 `.env` 文件（推荐）
  - 在 docker-compose.yml 同级目录创建 `.env` 文件
  - 在 docker-compose.yml 中使用 `env_file: .env`
  
- **方式2**：在 docker-compose.yml 中直接定义
  - 使用 `environment:` 部分定义环境变量
  
- **方式3**：使用 `-e` 参数（docker run 方式）
  - 不推荐，管理不便

⚠️ **重要提示**：
- 所有密钥类环境变量（`NEXTAUTH_SECRET`、`SALT`、`ENCRYPTION_KEY`）必须随机生成
- 不要将包含敏感信息的 `.env` 文件提交到版本控制系统
- 本地开发可以使用 `.env.example` 作为模板

## 三、Docker Compose 配置要点

### 1. 服务依赖顺序

确保服务启动顺序正确：
- **PostgreSQL** → 最先启动（数据库初始化需要时间）
- **ClickHouse** → 其次启动
- **Redis** → 然后启动
- **Langfuse Web/Server** → 最后启动（依赖上述服务）

在 docker-compose.yml 中使用 `depends_on` 确保启动顺序：
```yaml
services:
  langfuse-web:
    depends_on:
      - postgres
      - clickhouse
      - redis
```

### 2. 数据持久化配置

⚠️ **重要**：默认配置可能不持久化数据，容器删除后数据会丢失

- 为 PostgreSQL、ClickHouse、Redis 配置 volumes
- 为 Blob 存储（如 MinIO）配置 volumes
- 示例：
```yaml
volumes:
  postgres_data:
  clickhouse_data:
  redis_data:
```

### 3. 网络配置

- 确保所有服务在同一个 Docker 网络中
- 服务间通信使用服务名（如 `postgres`、`clickhouse`），而不是 `localhost`
- 端口映射要正确配置，避免端口冲突

### 4. 健康检查配置

建议为关键服务配置健康检查：
```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:3000/api/public/health"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 60s
```

## 四、启动和验证要点

### 1. 启动前检查清单

- [ ] Docker 服务正常运行
- [ ] 端口未被占用
- [ ] 环境变量已正确配置（特别是密钥类变量）
- [ ] `.env` 文件已创建（如果使用）
- [ ] docker-compose.yml 配置正确

### 2. 启动步骤

```bash
# 1. 进入 langfuse 目录
cd /path/to/langfuse

# 2. 检查配置
docker compose config

# 3. 拉取最新镜像（可选）
docker compose pull

# 4. 启动服务（后台运行）
docker compose up -d

# 5. 查看启动日志
docker compose logs -f
```

### 3. 验证服务状态

```bash
# 查看所有容器状态
docker compose ps

# 检查服务健康状态
curl http://localhost:3000/api/public/health

# 查看特定服务日志
docker compose logs -f langfuse-web
```

⚠️ **注意**：
- 首次启动需要较长时间（镜像下载、数据库初始化等）
- 等待所有服务状态为 "healthy" 或 "running" 后再访问
- 如果服务启动失败，查看日志排查问题

## 五、常见问题及解决方案

### 1. 服务启动失败

**问题**：容器启动后立即退出

**排查步骤**：
```bash
# 查看容器状态
docker compose ps -a

# 查看详细日志
docker compose logs langfuse-web

# 检查环境变量是否正确
docker compose config
```

**常见原因**：
- 环境变量缺失或配置错误（特别是必填变量）
- 数据库连接失败（检查 DATABASE_URL）
- 端口被占用
- 内存不足

### 2. 数据库连接失败

**问题**：`Connection refused` 或 `Connection timeout`

**解决方案**：
- 检查 PostgreSQL 容器是否正常运行：`docker compose ps postgres`
- 检查 DATABASE_URL 中的主机名是否为服务名（如 `postgres`），不是 `localhost`
- 等待数据库完全启动后再启动 Langfuse 服务
- 检查数据库初始化是否完成：`docker compose logs postgres`

### 3. 认证失败

**问题**：无法登录或认证错误

**解决方案**：
- 检查 `NEXTAUTH_URL` 是否与实际访问地址一致
- 检查 `NEXTAUTH_SECRET` 是否已正确设置
- 清除浏览器缓存和 Cookie 后重试
- 检查日志中的认证相关错误信息

### 4. 内存不足

**问题**：容器因内存不足被杀死（OOM）

**解决方案**：
- 增加 Docker Desktop 的内存分配
- 设置 `NODE_OPTIONS=--max-old-space-size=4096` 限制 Node.js 内存
- 减少其他运行中的容器或应用
- 检查系统可用内存：`docker stats`

### 5. 数据丢失

**问题**：重启容器后数据丢失

**解决方案**：
- 检查 volumes 配置是否正确
- 确认数据卷已挂载：`docker volume ls`
- 检查数据卷内容：`docker volume inspect <volume_name>`
- 确保 docker-compose.yml 中配置了持久化 volumes

## 六、性能优化建议

### 1. 资源配置

- **Web/Server 容器**：至少 2 CPU + 4 GB RAM
- **PostgreSQL**：至少 2 CPU + 4 GB RAM
- **ClickHouse**：推荐 2 CPU + 8 GB RAM（数据量大时）
- **Redis**：至少 1 CPU + 2 GB RAM

### 2. 本地开发 vs 生产环境

⚠️ **重要区别**：
- **本地开发**：适合测试、调试、低流量场景
- **生产环境**：需要高可用、备份策略、监控告警等
- Docker Compose 方式不适合生产环境的高可用需求

### 3. 数据备份

- 定期备份 PostgreSQL 数据
- 定期备份 ClickHouse 数据
- 备份 volumes 目录或使用数据库导出工具

## 七、安全注意事项

### 1. 密钥管理

- ⚠️ **绝对不要**使用默认密钥或示例密钥
- ⚠️ **绝对不要**将包含密钥的 `.env` 文件提交到 Git
- 使用强随机密钥生成工具：`openssl rand -base64 32`
- 生产环境考虑使用密钥管理服务（如 AWS Secrets Manager）

### 2. 网络安全

- 本地开发可以允许外部访问（`HOSTNAME=0.0.0.0`）
- 生产环境建议使用反向代理（Nginx、Traefik）并配置 HTTPS
- 限制数据库和 Redis 的访问权限（仅允许内部网络访问）

### 3. 数据安全

- 敏感数据会使用 `ENCRYPTION_KEY` 加密存储
- 确保 `ENCRYPTION_KEY` 安全保管，丢失后无法恢复数据
- 定期更新密钥（需要迁移数据）

## 八、更新和维护

### 1. 版本更新

```bash
# 拉取最新镜像
docker compose pull

# 重新创建容器（保留数据）
docker compose up -d --force-recreate

# 查看更新日志
docker compose logs -f
```

⚠️ **注意**：
- 更新前备份数据
- 查看更新日志了解破坏性变更
- 测试环境先验证更新

### 2. 日志管理

- 定期清理日志文件，避免占用过多磁盘空间
- 配置日志轮转策略
- 重要错误及时查看和处理

### 3. 监控建议

- 监控容器资源使用情况：`docker stats`
- 监控数据库连接数和性能
- 监控磁盘空间使用情况
- 设置告警机制（生产环境）

## 九、Mac 平台特殊注意事项

### 1. M1/M3 芯片兼容性

- 确保 Docker 镜像支持 ARM64 架构
- 如果镜像不支持，可能需要使用 `platform: linux/amd64`（性能可能受影响）
- 检查镜像架构：`docker inspect <image> | grep Architecture`

### 2. 资源限制

- Mac Docker Desktop 默认资源限制可能较低
- 在 Docker Desktop 设置中增加 CPU 和内存分配
- 关闭不必要的应用释放资源

### 3. 文件系统性能

- Docker Desktop 在 Mac 上使用虚拟化，文件系统性能可能较慢
- 考虑将数据卷放在 Docker 专用目录而不是共享目录
- 大量 I/O 操作时注意性能影响

## 十、快速检查清单

在开始搭建前，请确认：

- [ ] Docker 和 Docker Compose 已安装并运行
- [ ] 系统资源充足（至少 4 GB 可用内存）
- [ ] 端口 3000 未被占用
- [ ] 已生成所有必需的密钥（NEXTAUTH_SECRET、SALT、ENCRYPTION_KEY）
- [ ] 已创建 `.env` 文件并配置所有必填环境变量
- [ ] docker-compose.yml 配置正确（服务依赖、volumes、网络等）
- [ ] 已了解数据持久化配置

## 总结

本地搭建 Langfuse Docker 环境的关键在于：
1. **环境变量配置**：特别是密钥类变量必须随机生成
2. **服务依赖顺序**：确保数据库等服务先启动
3. **数据持久化**：配置 volumes 避免数据丢失
4. **资源充足**：确保有足够的内存和磁盘空间
5. **安全配置**：使用强密钥，不要暴露敏感信息

遵循以上要点，可以大大减少搭建过程中遇到的问题。
