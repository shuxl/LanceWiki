# 2 事务传播行为概念或介绍

## 2.1 什么是事务传播行为
事务传播行为（Transaction Propagation）定义了当一个事务方法被另一个事务方法调用时，Spring应该如何处理事务边界。它决定了是否创建新事务、加入现有事务，或者以非事务方式执行。

## 2.2 传播行为的作用
- **事务边界控制**：决定事务的开始和结束位置
- **事务嵌套处理**：处理事务方法之间的调用关系
- **数据一致性保证**：确保业务操作的原子性
- **性能优化**：避免不必要的事务开销

# 3 七种事务传播行为

## 3.1 REQUIRED（默认）
如果当前存在事务，则加入该事务；如果当前没有事务，则创建一个新的事务。

### 3.1.1 特点
- 默认的传播行为
- 最常用的传播行为
- 保证事务的完整性

### 3.1.2 实现原理
```java
public class TransactionAspectSupport {
    
    protected TransactionStatus handleExistingTransaction(TransactionDefinition definition, 
                                                       Object transaction) {
        // 检查传播行为
        if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRED) {
            // 如果存在事务，直接加入
            if (isExistingTransaction(transaction)) {
                return handleExistingTransaction(definition, transaction);
            }
            // 如果不存在事务，创建新事务
            else {
                return startTransaction(definition, transaction);
            }
        }
    }
}
```

### 3.1.3 使用场景
```java
@Service
public class UserService {
    
    @Transactional(propagation = Propagation.REQUIRED)
    public void createUser(User user) {
        // 创建用户
        userRepository.save(user);
        
        // 调用另一个事务方法
        profileService.createProfile(user.getId());
    }
}

@Service
public class ProfileService {
    
    @Transactional(propagation = Propagation.REQUIRED)
    public void createProfile(Long userId) {
        // 创建用户档案
        // 如果UserService有事务，则加入该事务
        // 如果UserService没有事务，则创建新事务
    }
}
```

## 3.2 REQUIRES_NEW
总是创建一个新的事务。如果当前存在事务，则将当前事务挂起。

### 3.2.1 特点
- 总是创建新事务
- 独立于调用方的事务
- 可以独立提交或回滚

### 3.2.2 实现原理
```java
public class TransactionAspectSupport {
    
    protected TransactionStatus startTransaction(TransactionDefinition definition, 
                                              Object transaction) {
        if (definition.getPropagationBehavior() == TransactionDefinition.PROPAGATION_REQUIRES_NEW) {
            // 挂起当前事务
            SuspendedResourcesHolder suspendedResources = suspend(transaction);
            
            // 创建新事务
            DefaultTransactionStatus status = newTransactionStatus(definition, transaction, true);
            status.setSuspendedResources(suspendedResources);
            
            doBegin(transaction);
            return status;
        }
    }
    
    protected void cleanupAfterCompletion(DefaultTransactionStatus status) {
        if (status.isNewTransaction()) {
            // 提交新事务
            doCommit(status);
            
            // 恢复挂起的事务
            resume(status.getSuspendedResources());
        }
    }
}
```

### 3.2.3 使用场景
```java
@Service
public class OrderService {
    
    @Transactional(propagation = Propagation.REQUIRED)
    public void createOrder(Order order) {
        // 创建订单
        orderRepository.save(order);
        
        // 发送通知（独立事务）
        notificationService.sendNotification(order);
        
        // 即使通知发送失败，订单创建仍然成功
    }
}

@Service
public class NotificationService {
    
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void sendNotification(Order order) {
        // 发送通知
        // 独立事务，失败不影响订单创建
    }
}
```

## 3.3 SUPPORTS
如果当前存在事务，则加入该事务；如果当前没有事务，则以非事务方式执行。

### 3.3.1 特点
- 支持事务但不强制要求
- 可以优化性能
- 适用于查询操作

### 3.3.2 使用场景
```java
@Service
public class UserService {
    
    @Transactional(propagation = Propagation.REQUIRED)
    public void updateUser(User user) {
        // 更新用户信息
        userRepository.save(user);
        
        // 查询用户统计信息（非事务）
        userStatsService.getUserStats(user.getId());
    }
}

@Service
public class UserStatsService {
    
    @Transactional(propagation = Propagation.SUPPORTS)
    public UserStats getUserStats(Long userId) {
        // 查询用户统计信息
        // 如果有事务则加入，否则非事务执行
        return userStatsRepository.findByUserId(userId);
    }
}
```

## 3.4 NOT_SUPPORTED
以非事务方式执行。如果当前存在事务，则将当前事务挂起。

### 3.4.1 特点
- 强制非事务执行
- 适用于不支持事务的操作
- 可以避免事务超时

### 3.4.2 使用场景
+ 下面这个场景会引起挂起的事务所占用的资源（如：数据库连接）不能释放，不是一个好例子
```java
@Service
public class FileService {
    
    @Transactional(propagation = Propagation.NOT_SUPPORTED)
    public void processLargeFile(String filePath) {
        // 处理大文件
        // 避免长时间占用事务连接
        processFile(filePath);
    }
}
```

## 3.5 MANDATORY
必须在事务中执行。如果当前没有事务，则抛出异常。

### 3.5.1 特点
- 强制要求事务环境
- 用于确保数据一致性
- 适用于关键业务操作

### 3.5.2 使用场景
```java
@Service
public class PaymentService {
    
    @Transactional(propagation = Propagation.MANDATORY)
    public void processPayment(Payment payment) {
        // 处理支付
        // 必须在事务中执行
        paymentRepository.save(payment);
        accountService.updateBalance(payment.getAccountId(), payment.getAmount());
    }
}
```

## 3.6 NEVER
不能在事务中执行。如果当前存在事务，则抛出异常。

### 3.6.1 特点
- 强制非事务环境
- 用于防止事务嵌套
- 适用于只读操作

### 3.6.2 使用场景
```java
@Service
public class ReportService {
    
    @Transactional(propagation = Propagation.NEVER)
    public Report generateReport(Date startDate, Date endDate) {
        // 生成报表
        // 确保在非事务环境中执行
        return reportRepository.generateReport(startDate, endDate);
    }
}
```

## 3.7 NESTED
如果当前存在事务，则创建一个嵌套事务；如果当前没有事务，则等同于REQUIRED。

### 3.7.1 特点
- 支持嵌套事务
- 可以独立回滚
- 需要数据库支持保存点

### 3.7.2 实现原理
```java
public class DataSourceTransactionManager {
    
    @Override
    protected void doBegin(Object transaction) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) transaction;
        Connection con = txObject.getConnectionHolder().getConnection();
        
        if (txObject.isNewTransaction()) {
            // 新事务
            con.setAutoCommit(false);
        } else if (txObject.hasTransaction()) {
            // 嵌套事务
            if (supportsSavepoints()) {
                // 创建保存点
                txObject.setSavepoint(con.setSavepoint());
            }
        }
    }
    
    @Override
    protected void doRollback(DefaultTransactionStatus status) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) status.getTransaction();
        
        if (status.isNewTransaction()) {
            // 回滚整个事务
            txObject.getConnectionHolder().getConnection().rollback();
        } else if (txObject.hasTransaction()) {
            // 回滚到保存点
            if (txObject.getSavepoint() != null) {
                txObject.getConnectionHolder().getConnection().rollback(txObject.getSavepoint());
            }
        }
    }
}
```

### 3.7.3 使用场景
```java
@Service
public class OrderService {
    
    @Transactional(propagation = Propagation.REQUIRED)
    public void createOrder(Order order) {
        // 创建订单
        orderRepository.save(order);
        
        try {
            // 创建订单详情（嵌套事务）
            orderDetailService.createOrderDetails(order.getId(), order.getItems());
        } catch (Exception e) {
            // 订单详情创建失败不影响订单创建
            log.error("Failed to create order details", e);
        }
    }
}

@Service
public class OrderDetailService {
    
    @Transactional(propagation = Propagation.NESTED)
    public void createOrderDetails(Long orderId, List<OrderItem> items) {
        // 创建订单详情
        // 如果失败，只回滚订单详情，不影响订单创建
        for (OrderItem item : items) {
            orderDetailRepository.save(new OrderDetail(orderId, item));
        }
    }
}
```

# 4 事务传播行为的实现原理

## 4.1 事务状态管理
Spring通过`TransactionStatus`管理事务状态：

```java
public class DefaultTransactionStatus implements TransactionStatus {
    
    private boolean newTransaction;
    private boolean hasTransaction;
    private boolean rollbackOnly;
    private Object suspendedResources;
    private Object savepoint;
    
    // 判断是否为新事务
    public boolean isNewTransaction() {
        return this.newTransaction;
    }
    
    // 判断是否有事务
    public boolean hasTransaction() {
        return this.hasTransaction;
    }
    
    // 设置回滚标记
    public void setRollbackOnly() {
        this.rollbackOnly = true;
    }
    
    // 判断是否只回滚
    public boolean isRollbackOnly() {
        return this.rollbackOnly;
    }
}
```

## 4.2 事务挂起和恢复
对于需要挂起当前事务的传播行为（如REQUIRES_NEW、NOT_SUPPORTED）：

```java
public abstract class AbstractPlatformTransactionManager {
    
    // 挂起事务
    protected final SuspendedResourcesHolder suspend(Object transaction) {
        if (TransactionSynchronizationManager.isSynchronizationActive()) {
            // 挂起事务同步
            TransactionSynchronizationManager.suspend();
        }
        
        // 挂起事务资源
        Object suspendedResources = doSuspend(transaction);
        
        return new SuspendedResourcesHolder(suspendedResources);
    }
    
    // 恢复事务
    protected final void resume(Object transaction, SuspendedResourcesHolder suspendedResources) {
        if (suspendedResources != null) {
            // 恢复事务资源
            doResume(transaction, suspendedResources.getSuspendedResources());
            
            // 恢复事务同步
            TransactionSynchronizationManager.resume();
        }
    }
}
```

## 4.3 事务嵌套处理
对于嵌套事务（NESTED传播行为）：

```java
public class DataSourceTransactionManager {
    
    // 判断是否支持保存点
    protected boolean supportsSavepoints() {
        try {
            return this.dataSource.getConnection().getMetaData().supportsSavepoints();
        } catch (SQLException ex) {
            return false;
        }
    }
    
    // 创建保存点
    protected void createSavepoint(DefaultTransactionStatus status) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) status.getTransaction();
        Connection con = txObject.getConnectionHolder().getConnection();
        
        try {
            txObject.setSavepoint(con.setSavepoint());
        } catch (SQLException ex) {
            throw new TransactionSystemException("Could not create JDBC savepoint", ex);
        }
    }
    
    // 回滚到保存点
    protected void rollbackToSavepoint(DefaultTransactionStatus status) {
        DataSourceTransactionObject txObject = (DataSourceTransactionObject) status.getTransaction();
        Connection con = txObject.getConnectionHolder().getConnection();
        
        try {
            con.rollback(txObject.getSavepoint());
        } catch (SQLException ex) {
            throw new TransactionSystemException("Could not roll back to JDBC savepoint", ex);
        }
    }
}
```

# 5 传播行为的选择策略

## 5.1 选择依据
1. **业务需求**：是否需要事务保证
2. **性能要求**：对性能的敏感程度
3. **数据一致性**：对数据一致性的要求
4. **异常处理**：异常情况下的处理策略

## 5.2 选择指南

### 5.2.1 写操作场景
- **REQUIRED**：大多数写操作的默认选择
- **REQUIRES_NEW**：需要独立事务的场景
- **MANDATORY**：必须在事务中执行的关键操作

### 5.2.2 读操作场景
- **SUPPORTS**：支持事务但不强制的查询操作
- **NOT_SUPPORTED**：强制非事务的查询操作
- **NEVER**：不能在事务中执行的查询操作

### 5.2.3 嵌套操作场景
- **NESTED**：需要部分回滚的嵌套操作
- **REQUIRES_NEW**：完全独立的嵌套操作

# 6 底层实现原理

## 6.1 传播行为处理流程
```java
public class TransactionAspectSupport {
    
    protected TransactionStatus handleExistingTransaction(TransactionDefinition definition, 
                                                       Object transaction) {
        switch (definition.getPropagationBehavior()) {
            case TransactionDefinition.PROPAGATION_REQUIRED:
                return handleExistingTransactionForRequired(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_REQUIRES_NEW:
                return handleExistingTransactionForRequiresNew(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_SUPPORTS:
                return handleExistingTransactionForSupports(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_NOT_SUPPORTED:
                return handleExistingTransactionForNotSupported(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_MANDATORY:
                return handleExistingTransactionForMandatory(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_NEVER:
                return handleExistingTransactionForNever(definition, transaction);
                
            case TransactionDefinition.PROPAGATION_NESTED:
                return handleExistingTransactionForNested(definition, transaction);
                
            default:
                throw new IllegalTransactionStateException("Unknown propagation behavior");
        }
    }
}
```

## 6.2 关键类图
```
TransactionDefinition (接口)
    ├── 定义传播行为常量
    ├── 定义隔离级别常量
    └── 定义超时和只读属性

TransactionStatus (接口)
    └── DefaultTransactionStatus (默认实现)
        ├── 跟踪事务状态
        ├── 管理回滚标记
        └── 管理挂起资源

TransactionSynchronizationManager (事务同步管理器)
    ├── 管理事务资源绑定
    ├── 管理事务同步器
    └── 提供事务上下文

SuspendedResourcesHolder (挂起资源持有者)
    ├── 保存挂起的事务资源
    └── 支持事务恢复
```
