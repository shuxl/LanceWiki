# 2 事务概念或介绍

## 2.1 什么是事务
事务（Transaction）是数据库操作的一个逻辑单元，它包含一组相关的操作，这些操作要么全部成功执行，要么全部失败回滚。事务确保了数据的一致性和完整性。

## 2.2 ACID特性
事务必须满足ACID四个特性：

### 2.2.1 原子性（Atomicity）
- **定义**：事务是不可分割的工作单位，事务中的操作要么全部成功，要么全部失败
- **实现原理**：通过日志记录和回滚机制实现
- **示例**：
```java
@Transactional
public void transferMoney(Account from, Account to, BigDecimal amount) {
    from.debit(amount);    // 扣款
    to.credit(amount);     // 存款
    // 如果任何一步失败，整个事务回滚
}
```

### 2.2.2 一致性（Consistency）
- **定义**：事务执行前后，数据库从一个一致性状态转换到另一个一致性状态
- **约束**：包括实体完整性、参照完整性、用户定义的完整性约束
- **示例**：转账前后总金额保持不变

### 2.2.3 隔离性（Isolation）
- **定义**：多个事务并发执行时，事务之间不会相互影响
- **问题**：脏读、不可重复读、幻读
- **解决方案**：通过锁机制和MVCC实现

### 2.2.4 持久性（Durability）
- **定义**：事务一旦提交，其结果就是永久性的
- **实现**：通过WAL（Write-Ahead Logging）机制保证

## 2.3 事务边界
事务边界定义了事务的开始和结束：

### 2.3.1 事务开始
- 显式开始：`BEGIN TRANSACTION`
- 隐式开始：执行第一条SQL语句时

### 2.3.2 事务结束
- **提交（Commit）**：永久保存事务的修改
- **回滚（Rollback）**：撤销事务的所有修改
- **自动提交**：某些数据库默认每条SQL都是独立事务

## 2.4 事务状态
事务在其生命周期中会经历以下状态：

1. **活动状态（Active）**：事务正在执行
2. **部分提交状态（Partially Committed）**：最后一条语句执行完成
3. **失败状态（Failed）**：事务无法继续执行
4. **中止状态（Aborted）**：事务回滚，数据库恢复到事务开始前的状态
5. **提交状态（Committed）**：事务成功完成

# 3 本地事务与分布式事务

## 3.1 本地事务
- **定义**：在单个数据库实例内执行的事务
- **特点**：简单、高效、ACID特性容易保证
- **示例**：
```java
@Transactional
public void updateUserInfo(User user) {
    userRepository.save(user);
    userProfileRepository.updateProfile(user.getProfile());
}
```

## 3.2 分布式事务
- **定义**：跨越多个数据库或服务的事务
- **挑战**：网络延迟、部分失败、一致性保证困难
- **解决方案**：
  - 2PC（两阶段提交）
  - 3PC（三阶段提交）
  - TCC（Try-Confirm-Cancel）
  - Saga模式
  - 最终一致性

# 4 Spring事务管理基本原理

## 4.1 核心组件
Spring事务管理基于以下核心组件：

### 4.1.1 PlatformTransactionManager
事务管理器接口，定义了事务的基本操作：
```java
public interface PlatformTransactionManager {
    TransactionStatus getTransaction(TransactionDefinition definition);
    void commit(TransactionStatus status);
    void rollback(TransactionStatus status);
}
```

### 4.1.2 TransactionDefinition
事务定义接口，定义了事务的属性：
```java
public interface TransactionDefinition {
    int getIsolationLevel();
    int getPropagationBehavior();
    int getTimeout();
    boolean isReadOnly();
}
```

### 4.1.3 TransactionStatus
事务状态接口，用于跟踪当前事务的状态：
```java
public interface TransactionStatus {
    boolean isNewTransaction();
    boolean hasTransaction();
    void setRollbackOnly();
    boolean isRollbackOnly();
}
```

## 4.2 事务管理流程
1. **事务开始**：调用`getTransaction()`方法
2. **业务执行**：在事务上下文中执行业务逻辑
3. **事务提交/回滚**：根据执行结果决定提交或回滚

## 4.3 关键设计思想

### 4.3.1 声明式事务
通过注解或XML配置声明事务属性，而非硬编码：
```java
@Transactional(
    propagation = Propagation.REQUIRED,
    isolation = Isolation.READ_COMMITTED,
    timeout = 30,
    readOnly = false
)
public void businessMethod() {
    // 业务逻辑
}
```

### 4.3.2 事务传播
定义了当一个事务方法被另一个事务方法调用时的行为：
- REQUIRED：默认传播行为，如果存在事务则加入，否则创建新事务
- REQUIRES_NEW：总是创建新事务
- SUPPORTS：如果存在事务则加入，否则以非事务方式执行
- NOT_SUPPORTED：以非事务方式执行
- MANDATORY：必须在事务中执行
- NEVER：不能在事务中执行
- NESTED：如果存在事务则创建嵌套事务

### 4.3.3 事务隔离级别
定义了事务之间的隔离程度：
- READ_UNCOMMITTED：读未提交，最低隔离级别
- READ_COMMITTED：读已提交，防止脏读
- REPEATABLE_READ：可重复读，防止不可重复读
- SERIALIZABLE：串行化，最高隔离级别，防止幻读

# 5 底层实现原理

## 5.1 代理机制
Spring事务管理基于AOP代理机制实现：

### 5.1.1 代理创建
```java
// 简化的代理创建过程
public class TransactionAspectSupport {
    protected Object invokeWithinTransaction(Method method, Class<?> targetClass, 
                                          final InvocationCallback invocation) {
        // 1. 获取事务属性
        TransactionAttribute txAttr = getTransactionAttributeSource()
            .getTransactionAttribute(method, targetClass);
        
        // 2. 获取事务管理器
        PlatformTransactionManager tm = determineTransactionManager(txAttr);
        
        // 3. 开始事务
        TransactionStatus status = tm.getTransaction(txAttr);
        
        try {
            // 4. 执行业务方法
            Object retVal = invocation.proceedWithInvocation();
            
            // 5. 提交事务
            tm.commit(status);
            return retVal;
        } catch (Throwable ex) {
            // 6. 回滚事务
            completeTransactionAfterThrowing(txAttr, status, ex);
            throw ex;
        }
    }
}
```

### 5.1.2 事务同步
Spring使用`TransactionSynchronizationManager`管理事务资源：
```java
public abstract class TransactionSynchronizationManager {
    private static final ThreadLocal<Set<TransactionSynchronization>> synchronizations =
        new NamedThreadLocal<>("Transaction synchronizations");
    
    private static final ThreadLocal<Map<Object, Object>> resources =
        new NamedThreadLocal<>("Transactional resources");
    
    // 注册事务同步器
    public static void registerSynchronization(TransactionSynchronization synchronization)
    
    // 绑定资源到当前事务
    public static void bindResource(Object key, Object value)
    
    // 获取当前事务的资源
    public static Object getResource(Object key)
}
```

## 5.2 关键类图
```
PlatformTransactionManager (接口)
    ├── DataSourceTransactionManager (数据源事务管理器)
    ├── JpaTransactionManager (JPA事务管理器)
    ├── HibernateTransactionManager (Hibernate事务管理器)
    └── JtaTransactionManager (JTA事务管理器)

TransactionDefinition (接口)
    ├── DefaultTransactionDefinition (默认实现)
    └── RuleBasedTransactionAttribute (基于规则的事务属性)

TransactionStatus (接口)
    └── DefaultTransactionStatus (默认实现)

TransactionSynchronizationManager (事务同步管理器)
    ├── 管理事务资源
    ├── 管理事务同步器
    └── 管理当前事务状态
```
