## 1.1 什么是注解处理器

注解处理器（Annotation Processor）是Java编译时处理注解的工具，它可以在编译阶段扫描和处理代码中的注解，生成新的源文件、字节码文件或进行编译时检查。

## 1.2 注解处理器的优势

1. **编译时处理**：在编译阶段就完成处理，避免运行时性能开销
2. **类型安全**：编译时检查，提供更好的类型安全保证
3. **代码生成**：可以自动生成样板代码，减少重复工作
4. **编译时验证**：可以在编译时进行各种验证和检查

# 3 注解处理器的实现步骤

## 3.1 创建注解

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.SOURCE)  // 编译时处理，不需要保留到运行时
public @interface Builder {
    String value() default "";
}
```

## 3.2 实现处理器

```java
@SupportedAnnotationTypes("com.example.Builder")
@SupportedSourceVersion(SourceVersion.RELEASE_8)
public class BuilderProcessor extends AbstractProcessor {
    
    private Elements elementUtils;
    private Filer filer;
    private Messager messager;
    
    @Override
    public synchronized void init(ProcessingEnvironment processingEnv) {
        super.init(processingEnv);
        this.elementUtils = processingEnv.getElementUtils();
        this.filer = processingEnv.getFiler();
        this.messager = processingEnv.getMessager();
    }
    
    @Override
    public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
        // 处理被@Builder注解标记的元素
        for (Element element : roundEnv.getElementsAnnotatedWith(Builder.class)) {
            if (element.getKind() != ElementKind.CLASS) {
                messager.printMessage(Diagnostic.Kind.ERROR, 
                    "@Builder can only be applied to classes", element);
                continue;
            }
            
            TypeElement classElement = (TypeElement) element;
            generateBuilderClass(classElement);
        }
        return true;
    }

    }
}
```

# 4 实际应用场景

## 4.1 代码生成

**Lombok**：通过注解自动生成getter、setter、构造函数等样板代码

```java

@Builder
@NoArgsConstructor
@AllArgsConstructor
```

**@Override**：验证方法确实重写了父类方法

## 4.3 依赖注入框架

Spring、Guice等框架使用注解处理器进行依赖注入的配置和验证。

# 5 注解处理器的处理流程

## 5.1 编译轮次（Rounds）

1. **初始化轮次**：处理器被初始化
2. **处理轮次**：处理注解，可能生成新的源文件
3. **最终轮次**：处理新生成的源文件中的注解
4. **完成**：所有注解处理完成

## 5.2 处理顺序

```java
@Override
public boolean process(Set<? extends TypeElement> annotations, RoundEnvironment roundEnv) {
    if (roundEnv.processingOver()) {
        // 最终轮次，进行清理工作
        return false;
    }
    
    // 处理当前轮次的注解
    for (Element element : roundEnv.getElementsAnnotatedWith(MyAnnotation.class)) {
        // 处理逻辑
    }
    
    return false; // 返回false表示不声明处理了这些注解
}
```

# 7 最佳实践

## 7.1 性能优化

- 缓存处理结果，避免重复计算
- 使用增量编译减少不必要的处理
- 合理使用 `getSupportedAnnotationTypes()` 限制处理范围

## 7.2 错误处理

- 提供清晰的错误信息
- 使用适当的错误级别（ERROR、WARNING、NOTE）
- 在错误情况下继续处理其他元素

## 7.3 代码生成

- 生成可读性好的代码
- 添加适当的注释
- 遵循Java编码规范

## 8.2 单元测试

使用 `compile-testing` 库进行单元测试：

```java
@Test
public void testProcessor() {
    JavaFileObject source = JavaFileObjects.forSourceString("TestClass",
        "package test;\n" +
        "@MyAnnotation\n" +
        "public class TestClass {}");
    
    JavaFileObject expectedOutput = JavaFileObjects.forSourceString("GeneratedClass",
        "package test;\n" +
        "public class GeneratedClass {}");
    
    assertAbout(javaSource())
        .that(source)
        .processedWith(new MyProcessor())
        .compilesWithoutError()
        .and()
        .generatesSources(expectedOutput);
}
```

# 9 常见问题和解决方案

## 9.1 处理器未被调用

- 检查 `META-INF/services` 文件是否正确配置
- 确认注解的 `@Retention` 设置为 `SOURCE`
- 验证编译命令是否正确

## 9.2 生成的代码无法编译

- 检查生成的代码语法
- 确保所有必要的导入都已添加
- 验证类型引用是否正确

## 9.3 性能问题

- 使用增量编译
- 缓存处理结果
- 避免不必要的文件I/O操作

# 10 注解处理器关联的其它知识

## 10.1 与反射的关系

注解处理器在编译时处理注解，而反射在运行时处理注解。两者互补：
- 注解处理器：编译时生成代码，提高运行时性能
- 反射：运行时动态获取和操作类信息

参考：[Java 反射杂谈](../old/100-Java基础-old/反射/java%20反射杂谈.md)

## 10.2 与动态代理的关系

注解处理器可以生成代理类的代码，而动态代理在运行时创建代理对象：
- 注解处理器：编译时生成代理类源码
- 动态代理：运行时创建代理对象

参考：[Java 动态代理](../old/100-Java基础-old/代理/Java%20动态代理.md)

## 10.3 与SPI机制的关系

注解处理器可以配合SPI机制自动生成服务提供者的注册代码：
- 注解处理器：生成SPI配置文件
- SPI机制：运行时发现和加载服务实现

参考：[SPI机制](./404-SPI机制.md)

## 10.4 与设计模式的关系

注解处理器常用于实现以下设计模式：
- **模板方法模式**：生成样板代码
- **建造者模式**：生成Builder类
- **工厂模式**：生成工厂类

参考：[设计模式基础](./202-设计模式基础.md)
